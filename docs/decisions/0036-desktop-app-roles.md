# ADR 0036 — 데스크톱 앱 역할 분리: Tauri는 전략 실행 Agent, Electron은 연구·백테스트

- **Status:** accepted
- **Date:** 2026-10-23
- **Amended:** 2026-10-23 — 첫 주문 증권사를 키움 모의투자로 바꾸고 한국투자(KIS)를 두 번째로 둔다(아래 개정 절, 설계는 [ADR 0037](0037-paper-order-execution.md)).
- **Supersedes in part:** SYSTEM_SPEC의 "No autonomous order execution is in scope"와 PROJECT_INSTRUCTIONS의 "do not implement autonomous execution unless explicitly re-scoped by the user" — 이 ADR이 그 사용자 재범위 지정이다. 범위는 아래 Gate로 제한한다.
- **Related:** [ADR 0028](0028-electron-desktop-shell.md)(Electron 셸), [ADR 0021](0021-backtest-engine.md)(백테스트), [ADR 0018](0018-broker-api-execution-ledger.md)(증권사 API 원장)

## Context

두 데스크톱 셸은 지금 같은 화면 빌드(`apps/desktop/dist`)를 띄우고 같은 일을 한다.

- **Tauri:** 2026-10-23 처음 빌드됐다(10 MB). API를 띄우지 않는다.
- **Electron:** 2026-10-22 사용자 요청으로 추가됐다. API를 직접 띄운다.

2026-10-23 사용자가 두 앱의 용도를 나누기로 했다.

- **Tauri:** 정해진 전략에 따라 매수·매도를 실행하는 Agent용.
- **Electron:** 사용자와 AI가 함께 논의하며 전략을 연구하고 백테스트하는 용도.

같은 날 사용자가 정한 세부 사항:

- **첫 주문 범위:** 모의투자만.
- **첫 주문 증권사:** 한국투자(KIS). 현재 조회 전용 연동이 있고, 공식 open-trading-api에 모의투자 도메인(`vps`)이 있다. (같은 날 개정: 키움이 첫 증권사, KIS는 두 번째. 아래 개정 절.)
- **이번 작업 범위:** 결정 기록과 두 앱의 구분까지. 주문 코드는 없다.
- **Electron의 주문:** 지금은 없다. 나중에 Gate에서 다시 검토할 수 있다.

## Decision

### 역할

|           | Tauri — **SIW Agent**                                                 | Electron — **SIW Research**                   |
| --------- | --------------------------------------------------------------------- | --------------------------------------------- |
| 목적      | 승인된 전략을 정해진 규칙대로 실행                                    | 사용자·AI 공동 전략 연구, 차트 복기, 백테스트 |
| 주문      | 단계적으로 허용(아래 Gate). 첫 단계는 모의투자만(키움 먼저, KIS 다음) | 없음. 이후 Gate에서 재검토 가능               |
| 전략 입력 | Research에서 검증·승인한 전략 버전만(버전 고정)                       | 전략 작성·수정·백테스트·워크포워드            |
| 번들 ID   | `com.pensivetraveler.siw.agent`                                       | `com.pensivetraveler.siw.research`            |

### 주문 Gate(Tauri)

각 단계는 사용자의 별도 명시 승인이 있어야 시작한다. 이 ADR은 단계 1의 설계 착수까지만 승인한다.

1. **모의투자 주문(키움 먼저, KIS 다음).**
   - 증권사마다 모의투자 도메인만 호출할 수 있게 코드에서 막는다. 실계좌 도메인을 고를 수 있는 설정은 두지 않는다.
   - 주문 원장은 기존 4개 원장과 분리한다. 원장 유형은 실제 증권사 체결, 사용자 수동 실제 체결, 가상 시나리오, 백테스트 체결이다. 모의 주문·체결은 실제 체결로 섞지 않는다.
   - 주문 의도에는 전략 버전, 입력 데이터 시점, 신호 근거, 수량·가격 계산을 기록한다.
   - 한도(종목·주문 금액·일 주문 수·일 손실)와 즉시 중지(킬 스위치)를 둔다.
2. **실계좌, 주문마다 사용자 승인.** 단계 1의 운영 기록을 보고 따로 결정한다.
3. **실계좌, 한도 안 자동.** 단계 2 이후 따로 결정한다.

### 변하지 않는 규칙

- 키·토큰·계좌번호는 코드·로그·커밋에 남기지 않는다. 기존 키체인 방식을 따른다.
- 실계좌 주문 엔드포인트는 단계 2가 승인되기 전까지 호출하지도 시험하지도 않는다.
- Agent가 만든 전략 코드는 실행 전에 사용자 검토·승인을 받는다(기존 규칙).
- 미래 데이터 차단, 확정 봉만 사용, 출처·시점 기록은 실행 Agent에도 그대로 적용한다.

### 이번 작업에서 한 것

- 이 ADR과 AGENTS.md·SYSTEM_SPEC·PROJECT_INSTRUCTIONS의 해당 문장 갱신.
- 두 앱의 이름·번들 ID·창 제목 구분. 화면 기능과 API는 바꾸지 않았다. 두 앱은 아직 같은 화면을 띄운다.

## Alternatives

- **한 앱에 연구와 실행을 함께 둔다:** 연구 중 실수로 주문할 길이 생기고, 권한·키 범위를 나누기 어렵다.
- **Electron을 실행용, Tauri를 연구용으로 둔다:** Electron은 API를 직접 띄우는 편의가 있어 연구 앱에 맞는다. Tauri는 가볍고(10 MB) Rust 본체에서 프로세스·권한을 좁게 다룰 수 있어 상시 실행 Agent에 맞는다.
- **처음부터 실계좌 주문:** 사용자가 모의투자부터 하기로 했다.

## Consequences

- **화면 분리:** 이후 화면을 앱별로 나눠야 한다. 예를 들어 실행 앱에는 전략 실행 상태·주문 원장·킬 스위치를, 연구 앱에는 백테스트·AI 논의를 둔다. 방법(빌드 분리 또는 셸 감지)은 단계 1 설계에서 정한다.
- **Tauri 앱의 API:** Tauri 앱도 API를 직접 띄우거나 상주 실행기를 갖춰야 한다. 지금은 API가 먼저 실행 중이어야 한다.
- **기존 설치:** 이름이 바뀌어 기존 `Stock Intelligence Workstation.app`과 따로 설치된다. 이전 앱은 사용자가 지운다.

## Revisit when

- 단계 1 모의투자 운영 기록이 쌓여 단계 2(실계좌, 주문마다 승인)를 검토할 때.
- Electron 연구 앱에서 주문이 필요하다는 요구가 생길 때.
- 키움·KIS 외 증권사(토스·메리츠)로 주문을 넓힐 때.

## Amendment 2026-10-23 — 첫 증권사는 키움 모의투자

- **사용자 결정:** "모의투자는 키움증권도 할 수 있게 해줘. KIS는 현재 API를 등록 못한 상태야."
- **변경:**
  - 단계 1의 첫 증권사는 키움 모의투자다. 키움은 조회 전용 연동이 있고(ADR 0029), 공식 스펙의 모든 API 페이지에 모의투자 도메인 `https://mockapi.kiwoom.com`이 있다.
  - KIS 모의투자는 같은 주문 계약 뒤의 두 번째 adapter로 남는다. 사용자가 KIS API를 등록한 뒤 구현한다.
  - 두 증권사 모두 코드에서 모의 도메인만 호출할 수 있다. 키움은 실전과 모의가 도메인으로만 갈리므로 host 검사가 차단선이다.
- **미검증:** 키움 모의 서버가 미국 주식 주문을 받는지는 문서만으로 알 수 없다. 첫 모의 호출 때 확인한다.
- **설계:** [ADR 0037](0037-paper-order-execution.md)(proposed).
