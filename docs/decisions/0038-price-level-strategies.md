# ADR 0038 — 가격대 진입형 전략: 미리 걸어 두는 지정가와 실시간 돌파 (초안)

- **Status:** proposed (설계 초안. 구현은 사용자의 별도 명시 승인이 있어야 시작한다)
- **Date:** 2026-10-24
- **Related:** [ADR 0037](0037-paper-order-execution.md)(모의 주문 실행기), [ADR 0031](0031-backtest-order-types.md)(백테스트 지정가·스톱), [ADR 0021](0021-backtest-engine.md)(백테스트 엔진), [ADR 0019](0019-toss-realtime-relay-and-tick-store.md)(토스 실시간 중계·틱 저장)

## Context

- **사용자 요구(2026-10-24):** "strategy 중 특정 가격대에 캔들이 진입할 시, 자동적으로 매수매도가 진행되는 경우도 있어."
- **지금 지원하는 방식:** 실행기와 규칙 전략은 **봉 마감 판단형**뿐이다.
  - 확정된 봉을 보고 판단하고, 그 뒤 주문한다.
  - ADR 0037 개정으로 실행 계획마다 봉 확정 대기를 정할 수 있게 됐다(0~900초).
  - 가격이 어떤 값에 닿는 순간 주문해야 하는 전략에는 이 대기가 맞지 않는다.
- **백테스트:** 지정가·스톱 주문을 지원한다(ADR 0031).
  - 가격은 신호 봉 종가 기준 비율(`offset_pct`)이나 절대 가격이다.
  - 체결은 다음 봉부터 확인한다. 지정가는 가격을 "뚫고 지나가야" 체결로 본다.
  - 봉 안의 가격 순서는 모르므로 보수적으로 본다.
- **키움 모의의 확인된 사실(2026-10-23):**
  - 지정가(`00`)만 받는다. 시장가(`03`)는 RC4065로 거절된다.
  - 스톱 주문 코드는 미국 주문 api-id 스펙에 없다(조회 응답의 `frgn_trde_tp`에는 34·35가 있다). 모의 지원 여부는 미확인이다.
  - 정규장에만 주문을 받는다. 프리마켓 주문은 RC4058로 거절된다.
- **실시간 가격 출처:**
  - 토스 실시간 중계와 틱 저장소가 있다(ADR 0019, 조회 전용).
  - Alpaca 유료 SIP 실시간 스트림은 계약이 있지만, 이 앱은 아직 연결하지 않았다.

## 두 가지 경우

|                | 미리 걸어 두는 지정가                                                | 돌파(스톱)                                                                                                                    |
| -------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 예             | "$340 이하로 내려오면 산다", "$360 이상 오르면 판다"                 | "$360을 뚫고 오르면 산다", "$330 아래로 깨지면 판다"                                                                          |
| 방향           | 지금 가격보다 유리한 쪽                                              | 지금 가격보다 불리한 쪽                                                                                                       |
| 주문 방식      | 지정가를 증권사에 미리 넣어 둔다. 증권사가 그 가격에서 바로 체결한다 | 원래는 스톱 주문이다. 키움 모의는 지정가만 받으므로 실행기가 실시간 체결가를 지켜보다가 닿는 순간 바로 체결될 지정가를 보낸다 |
| 대기 시간      | 없음(증권사 쪽 체결)                                                 | 실시간 가격 수신 + 주문 왕복 시간                                                                                             |
| 필요한 새 기능 | 주문을 미리 걸고, 유효 기간과 취소를 관리                            | 실시간 체결가로 조건을 판단하는 감시기                                                                                        |

## Decision (제안)

### 1. 전략 정의: `levels` 규칙

- 규칙 전략에 가격대 항목을 더한다. 기존 `entry`/`exit` 봉 조건과 같이 쓸 수 있다.
  ```
  "levels": [
    {"side": "buy",  "kind": "limit", "price": {"value": 340}, "quantity": 1, "valid": "session"},
    {"side": "buy",  "kind": "stop",  "price": {"indicator": "prev_day_high"}, "buffer_bps": 20},
    {"side": "sell", "kind": "limit", "price": {"from_entry_pct": 3}},
    {"side": "sell", "kind": "stop",  "price": {"from_entry_pct": -2}}
  ]
  ```
- 가격은 절대값, 확정된 봉으로 계산한 지표값(예: 전일 고가), 진입가 대비 비율 중 하나다.
- 지표값은 **확정된 봉만**으로 계산한다. 그 값을 쓸 수 있는 시점(예: 다음 세션 시작)부터만 유효하다. 그래서 미래 데이터가 섞이지 않는다.
- 각 가격대 항목에는 수량, 유효 기간(`session`/`day`/`until_cancel`), 돌파용 버퍼를 둔다.

### 2. 미리 걸어 두는 지정가

- **주문 시점:** 실행기가 무장되고 정규장이 열린 뒤, 가격대가 유효해지면 지정가를 건다.
- **기록:** 걸 때 의도(ADR 0037 계약)를 하나 남긴다. 의도에는 가격대 정의, 계산에 쓴 데이터 시점, 한도 검사 결과를 담는다.
- **관리:**
  - 유효 기간이 끝나거나 실행 계획이 바뀌면 취소한다.
  - 정규장 마감 전에 당일 유효 주문을 취소할지는 미결이다.
- **체결:** 기존 당일 주문 조회로 동기화한다. 체결 시각은 증권사가 준 값이다.
- **한도:** 1건 금액은 지정가 기준이다. 일 주문 수는 거는 시점에 센다.

### 3. 돌파: 실시간 감시기

- **방식:** 실행기 안에 가격 감시기를 둔다. 실시간 체결가가 기준가에 닿거나 넘으면 바로 체결될 지정가를 보낸다(매수는 기준가 × (1 + 버퍼), 매도는 × (1 − 버퍼)).
- **기록:** 근거로 트리거가 된 체결의 시각·가격·출처를 의도에 남긴다. 그 체결은 가격대가 유효해진 뒤의 것이어야 한다.
- **실시간 출처(미결):**
  - (a) Alpaca SIP 실시간 스트림: 시세 기본 공급업체(ADR 0035)와 같은 출처다. 연결 코드는 새로 만든다.
  - (b) 토스 실시간 중계: 이미 연결돼 있다. 다만 시세 출처와 주문 판단 출처가 달라진다.
- **안전:**
  - 실시간 연결이 끊기거나 체결 시각이 오래되면 새 돌파 주문을 내지 않는다.
  - 같은 가격대는 한 번만 발동한다.

### 4. 백테스트와의 대응

- **지정가:** ADR 0031과 같다. 가격대가 유효해진 다음 봉부터, 봉이 그 가격을 뚫고 지나가면 체결이다. 갭이면 시가에 체결한다.
- **돌파:** 스톱과 같다. 봉 고가·저가가 기준가를 지나면 발동하고, 기준가(갭이면 시가)에 슬리피지를 더해 체결한다.
- **한계:** 봉 안의 순서는 모른다. 같은 봉 안에서 진입과 손절·익절이 함께 닿으면 보수적으로 본다(ADR 0021). 틱 재현은 하지 않는다.
- **실시간과의 차이:** 백테스트는 봉 단위다. 실행은 실시간 체결가와 주문 왕복 시간 때문에 체결가가 다르다. 기록으로 비교한다.

### 5. 킬 스위치와의 관계(미결)

- 2026-10-23 사용자 결정: 킬 스위치는 "신규 주문만 중지"다.
- 미리 걸어 둔 지정가는 이미 증권사에 들어간 주문이다. 그래서 킬 스위치를 눌러도 체결될 수 있다.
- 미리 건 지정가만은 킬 스위치 때 취소할지 사용자 결정이 필요하다.

## 구현 단위(각각 사용자 승인 후)

1. **L1:** `levels` 정의·검증, 백테스트 지정가·돌파 체결(ADR 0031 확장), 시험.
2. **L2:** 실행기의 미리 걸어 두는 지정가(걸기·유효 기간·취소·동기화). 가짜 키움 서버로 시험한 뒤, 정규장에 사용자 확인을 받고 모의 주문으로 확인한다.
3. **L3:** 실시간 감시기와 돌파. 실시간 출처를 결정한 뒤 진행한다. 가짜 스트림으로 시험한 뒤 모의 주문으로 확인한다.

## Alternatives

- **봉 확정 대기를 0초로 두고 봉 조건으로 흉내 낸다:** 1분 늦게 반응하고, 봉 안에서 닿았다가 돌아온 가격을 놓친다.
- **증권사 스톱 주문을 쓴다:** 키움 모의는 지정가만 받는다. 실계좌·KIS에서 지원하면 adapter 기능으로 다시 검토한다.
- **틱 단위 백테스트:** 정확하지만, 틱 데이터와 저장·권리 문제가 크다(ADR 0019는 틱을 봉과 따로 둔다).

## 미결 질문(사용자 결정 필요)

1. 실시간 출처: Alpaca SIP 스트림 / 토스 실시간 중계.
2. 킬 스위치를 누를 때 미리 건 지정가를 취소할지.
3. 당일 유효 지정가를 정규장 마감 전에 취소할지.
4. 첫 구현 범위: L1+L2(지정가)부터 / L3(돌파)까지.

## Revisit when

- 키움·KIS의 스톱 주문 지원이 확인될 때.
- 실시간 출처가 정해질 때.
