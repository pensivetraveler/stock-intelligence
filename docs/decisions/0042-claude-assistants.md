## 기능별 기획(초안)

### 1. 보조지표 만들기 (Pine 편집기 옆 대화)

- 사용자가 원하는 지표를 말로 설명한다. Claude는 Pine 코드와 짧은 설명을 낸다.
- 앱이 그 코드를 현재 차트 봉으로 미리 실행한다(ADR 0040 인터프리터).
  - 오류(줄·칸)나 지원하지 않는 함수가 나오면 오류 문구를 Claude에 돌려 고치게 한다. 최대 5회 뒤에는 멈추고 사용자에게 보인다(2026-10-28 결정).
  - 미리보기는 차트에 임시로만 그린다. "적용"을 눌러야 지표로 저장된다.
- Claude에는 ADR 0040의 지원 범위·미지원 목록을 함께 준다. 미지원 기능을 쓰지 않게 한다.
- 차트 이미지(현재 화면 범위, 미래 봉 없음)를 붙여 "이 모양을 잡아내는 지표"를 요청할 수 있다.

### 2. 전략 연구 (백테스트 화면 옆 대화)

- 아이디어 논의 → Claude가 Pine strategy 초안 → 사용자가 차트 백테스트 실행.
- 백테스트 결과(순손익, 승률, 손익비, 최대 낙폭, 거래 수, 봉 안 가정 체결 건수)를 Claude가 읽고 문제점·개선안을 낸다.
  - 거래 수가 적을 때의 신뢰도, 과최적화 위험을 반드시 언급하게 한다.
  - 매수·매도 권고는 하지 않는다(ADR 0022 규칙 유지).
- 확정 시 Claude가 규칙 빌더 전략으로 변환한다.
  - 변환 후 두 백테스트(Pine, 규칙 빌더)를 같은 기간으로 나란히 비교한다. 차이가 크면 확정 전에 경고한다.
  - 규칙 빌더로 표현 못 하는 조건은 목록으로 남기고, 규칙 빌더 확장 작업으로 넘긴다(아래 "열린 질문").
- 확정된 규칙 빌더 전략만 버전이 붙어 워크포워드·SIW Agent로 이어진다(ADR 0036).

### 3. 매매 복기 (매매일지·차트 안 패널)

- **거래 1건:** 진입~청산 체결 묶음. 지금의 복기 Agent 근거에 진입·청산 시점 차트 이미지(시점까지)와 사후 이미지(분리 표시)를 더한다.
- **기간 리뷰:** 주간·월간 거래 전체. 승률·손익·보유기간·태그별 성과, 반복되는 실수 패턴을 사실로 계산해 보낸다.
- **전략·규칙 대비 점검:**
  - 매매 원칙 문서(글, 버전)와 거래를 대조한다.
  - 저장된 규칙 빌더 전략이 그 시점에 신호를 냈는지 기계적으로 계산해 사실로 보낸다.
  - 거래 메모·태그를 함께 보낸다(사후 작성 표시 유지).
- 리포트가 먼저 나오고, 그 아래에서 이어서 질문한다. 후속 대화도 같은 분석에 추가만 한다.

#### 매매 복기 상세(2026-10-26 사용자 결정, 첫 구현 대상)

- **화면:** 전용 "복기" 화면.
  - 왼쪽: 거래 목록(종목, 기간, 손익, 전략, 태그, 복기 완료 표시).
  - 가운데: 차트(진입·청산 표시).
  - 오른쪽: 리포트·후속 대화.
- **거래와 전략 연결:**
  - 증권사 체결에는 전략 정보가 없다. 사용자가 체결(또는 묶음)에 전략을 붙인다.
  - 저장된 규칙 전략이 그 시점에 신호를 냈으면 "이 전략 같아요"로 추천한다. 확정은 사용자가 한다.
- **거래 1건의 정의는 전략마다 다르다.** 전략에 묶음 규칙을 둔다.
  - 보유 0→0: 분할 매수·매도를 포함해 포지션이 닫힐 때까지(스윙형).
  - 하루 단위: 그날 그 종목 매매 전체(데이트레이딩형).
  - 진입 1회마다: 매수와 그것을 닫는 매도의 FIFO 짝(스캘핑형).
  - 수동 지정: 사용자가 체결을 골라 묶는다.
  - 전략을 붙이지 않은 체결은 보유 0→0으로 묶고 "전략 없음"으로 표시한다. 전략을 붙이면 그 규칙으로 다시 묶는다.
  - 묶음은 지금처럼 계좌별로 따로 한다(계좌별 FIFO 유지).
- **거래 1건 리포트 내용:**
  - 진입 타이밍: 추세·지표·거래량·일중 범위 내 위치, 추격 매수 여부.
  - 청산·보유 관리: MFE/MAE, 최대 이익 대비 실현 비율, 손실 방치 여부.
  - 분할·비중: 분할 매매가 평단가에 미친 영향, 계좌 대비 비중(잔고를 알 때만).
  - 사후 가정 비교(사후 정보로 표시):
    - 원칙 문서의 숫자 항목(손절·목표·보유기간)을 지켰다면;
    - 연결된 규칙 전략의 신호대로 했다면.
- **기간 리뷰:**
  - 누를 때만 만든다. 기간(주·월·직접 지정), 계좌·전략 필터를 고른다.
  - 사실 통계는 Claude 없이 항상 보인다. Claude 해설은 요청할 때만 받는다.
  - 묶어 보는 기준: 태그·종목, 시간대(프리마켓·장 초반 30분·정규장·애프터)·요일, 보유기간·포지션 규모.
- **매매 원칙 문서:**
  - 공통 원칙과 전략별 원칙을 한 줄씩 항목으로 적는다. 버전을 남긴다.
  - 숫자가 있는 항목(예: 손절 -7%)은 앱이 기계적으로 판정한다. 나머지는 Claude가 판단하고 판단임을 표시한다.
- **복기 결과물:**
  - 거래마다 복기 완료 표시.
  - 반복되는 실수가 보이면 Claude가 원칙 추가·수정을 제안한다. 사용자가 승인해야 원칙 문서에 반영된다(새 버전).

### 공통

- **대화 저장:** 기능별 대화(메시지, 보낸 내용, 모델, 시각, 토큰 수)를 로컬 SQLite에 저장한다. 목록 화면에서 모아 본다.
- **보낼 내용 미리보기:** 지금처럼 보내기 전에 내용(사실·이미지)을 볼 수 있다.
- **근거와 추론 분리:** 응답은 근거 인용·추론·가설·질문·불확실성으로 나눈다(ADR 0022).
- **생성 코드:** Pine·규칙은 사용자가 적용을 눌러야 저장·실행된다(AGENTS.md).

## 매매 복기 구현 단계(2026-10-26 사용자 승인)

1. 거래 묶음·전략 지정·메모·태그·복기 완료·복기 화면(Claude 호출 없음). 구현 기록은 `PROJECT_STATE.md`의 "매매 복기 1단계".
   - 매수 없는 매도는 공매도로 보지 않고 "짝 없음"으로 둔다(미국 현금 계좌 기준, 데이터 시작 전 보유분 가능성).
   - 거래 ID는 규칙과 첫 체결로 정한다. 규칙·전략을 바꾸면 이전 메모와 이어지지 않는다.
2. 거래 1건 리포트: 분석 항목 추가, 시점까지 그린 차트 이미지, 후속 질문, 모델 선택.
   - **2단계 상세(2026-10-26 사용자 결정):**
     - **리포트 형태:**
       - 맨 위에 한 줄 요약을 둔다.
       - 그 아래 항목별 섹션을 둔다: 진입 타이밍, 청산·보유, 분할·비중.
       - 섹션마다 근거 사실, 잘한 점, 아쉬운 점, 다음에 확인할 것을 적는다.
     - **생성:** 거래 상세의 "Claude 리포트" 버튼을 눌렀을 때만 만든다. 보낼 내용(사실·이미지·메모)을 먼저 보인다. 자동 생성과 일괄 생성은 하지 않는다.
     - **차트 이미지:** 화면 캡처가 아니라 따로 그린다.
       - 진입 시점까지: 첫 매수 봉까지만 그린다.
       - 청산 시점까지: 진입~청산 구간까지 그리고, 청산 이후 봉은 없다.
       - 상위 시간대 맥락: 진입일 기준 일봉, 진입 시점까지.
       - 청산 이후 이미지는 보내지 않는다.
     - **메모·태그:** "체결 후 작성한 본인 메모"로 구분해 보낸다.
     - **추가 사실(진입 시점 이전 데이터):**
       - 같은 날 SPY·QQQ 흐름과 종목의 상대 강도;
       - 전일 종가 대비 갭, 프리마켓 고가 대비 진입가;
       - 계좌 대비 비중.
     - **계좌 크기:** 사용자가 계좌마다 "이 날부터 운용금 X"를 기간별로 입력한다. 입력이 없는 기간의 거래는 비중을 계산하지 않고 그렇다고 표시한다.
     - **모델:** 기본값은 Sonnet. 설정에서 바꿀 수 있고, 응답마다 사용한 모델을 기록한다.
     - **후속 질문:** 대화를 이어 가고 저장한다. Claude는 읽기 전용 도구로 앱에 데이터를 더 요청할 수 있다. 요청마다 화면에 표시한다.
       - 이 종목의 다른 시간대·구간 봉과 지표;
       - 지수·다른 종목의 봉;
       - 연결된 규칙 전략이 그 시점에 신호를 냈는지(3단계 내용의 일부를 앞당김).
       - 내 다른 거래는 도구로 주지 않는다.
     - **도구 데이터의 시점:** 기본은 청산 시점까지다. 청산 이후 데이터도 받을 수 있지만 모두 "사후 정보"로 표시하고, 답에서도 구분하게 한다.
     - 계좌번호·키·기록 ID는 지금처럼 보내지 않는다.
   - **2a 구현:** 리포트·이미지·추가 사실·계좌 운용금·모델 설정(PR #97). 후속 질문은 2b로 나눴다.
   - **2b 상세(2026-10-27 사용자 결정):**
     - **대화 단위:** 리포트마다 대화 하나. 리포트 때 보낸 사실·이미지·리포트를 이어 쓰고, 새 리포트는 새 대화다. 대화는 저장하고 다시 열 수 있다.
     - **도구 실행:** 모두 읽기 전용이라 바로 실행한다. 대화에 "요청: SPY 5분봉 …"처럼 요청과 결과 요약을 보인다. 질문 하나에 데이터 요청은 최대 6번이다.
     - **도구가 돌려주는 것:** 계산된 수치와 요약 봉(OHLC 표, 많아야 100개 안팎), 그리고 Claude가 요청하면 차트 이미지. 이미지 수는 따로 제한하지 않고 6번 한도 안에서 쓴다.
     - **이미지 그리기:** 화면이 그린다(리포트 이미지와 같은 코드). API가 "이미지 필요"와 잘린 봉을 돌려주면 화면이 PNG로 그려 돌려주고, API가 대화를 이어 간다. 새 의존성은 넣지 않는다.
     - **전략 신호 도구:** 거래에 연결된 전략과 저장된 다른 규칙 전략. 전략 이름과 규칙 정의는 보낸다.
3. 원칙·대조: 매매 원칙 문서, 숫자 항목 판정, 사후 가정 두 가지, 전략 추천.
   - **3단계 상세(2026-10-27 사용자 결정):**
     - **원칙 입력:** 사용자가 원칙을 글로 쓰면 Claude가 항목으로 바꿔 제안한다. 숫자로 판정할 수 있는 항목은 종류와 값으로, 나머지는 글 항목으로 바꾼다. 사용자가 확인해야 저장되고, 저장할 때마다 새 버전이 된다. 공통 원칙과 전략별 원칙을 둔다.
     - **숫자 항목 종류:**
       - 손절·익절 %(평균 매수가 대비);
       - 비중 한도(계좌 운용금 대비 %);
       - 진입 조건 제한: 장 시작 후 N분 안 진입 금지, 전일 종가 대비 +X% 이상 갭 추격 금지, 하루 거래 N회 이하.
       - 최대 보유 기간은 이번 범위가 아니다.
     - **판정 대상 버전:** 기본은 거래일에 효력이 있던 버전이다. 원칙 문서가 없던 시기의 거래는 현재 버전으로 점검하고 "사후 원칙"으로 표시한다. 현재 버전과의 차이도 보인다.
     - **보이는 곳:**
       - 거래 상세: 항목별 지킴/어김/판단 불가를 항상 보인다(Claude 비용 없음).
       - 거래 목록: "원칙 어김 N" 열과 필터를 둔다.
       - Claude 리포트: 판정 결과와 글 원칙을 근거로 보낸다. 글 원칙은 Claude가 판단하고 판단임을 표시한다.
     - **계산 범위:** 봉이 필요한 판정(보유 중 손절가 도달, 갭 추격 등)도 백그라운드로 계산해 저장한다. 최근 90일 거래는 자동으로 계산하고, 그보다 오래된 거래는 사용자가 기간을 골라 "점검 실행"을 누를 때 계산한다. 진행률을 보인다.
     - **"원칙대로 했다면":** 실제 진입은 그대로 두고 원칙의 손절·익절 가격에 처음 닿은 시점에 청산했다면의 손익을 계산한다. 한 봉 안에서 둘 다 닿으면 1분봉으로 다시 확인한다. 그래도 같으면 손절이 먼저라고 보고 그 가정을 표시한다.
     - **"전략 신호대로 했다면":** 진입도 전략대로 한다. 같은 구간(단타는 그 거래일 세션, 스윙은 내 진입 10거래일 전부터 청산일까지)에서 전략의 첫 진입 신호 다음 봉 시가에 사서 청산 신호 다음 봉 시가에 팔았다면의 손익을 계산한다. 구간 안에 신호가 없으면 "전략은 진입하지 않았음"으로 표시한다.
     - **전략 추천:** 전략이 없는 거래를 열면 저장된 규칙 전략의 진입 규칙을 5분봉과 일봉으로 모두 확인한다. 진입 직전 봉에서 성립한 전략을 "이 전략 같아요"로 보이고, 확정은 사용자가 한다.
4. 기간 리뷰: 묶음 통계, Claude 해설, 원칙 수정 제안.
   - **4단계 상세(2026-10-27 사용자 결정):**
     - **대상:** 고른 기간(주·월·직접 지정)에 청산된 거래. 원장·계좌·전략 필터를 쓴다. 통화(USD·KRW)는 섞지 않고 통화별로 따로 계산한다.
     - **통계(Claude 없이 항상):**
       - 기본 성적: 거래 수, 승률, 평균 이익·손실, 손익비, 거래당 기대값, 수수료 합계;
       - 위험: 누적 손익 최대 낙폭, 최장 연속 손실, 최대 손실 거래 비중;
       - 원칙 대비: 항목별 어김 횟수, 어긴 거래와 지킨 거래의 손익 비교;
       - 사후 가정 합계: 원칙대로 했다면의 손익 합계와 실제의 차이(사후 정보). 계산된 거래만 합하고 빠진 건수를 보인다.
       - 묶음별 표: 태그·종목, 시간대(프리마켓·장 초반 30분·정규장·애프터)·요일, 보유기간·포지션 규모.
     - **사후 가정 계산:** 원칙 점검과 같은 백그라운드 작업에서 원칙 가정도 계산해 저장한다.
     - **그림:** 누적 손익 곡선(낙폭 포함), 묶음별 막대, 일별 손익 달력.
     - **이전 기간 비교:** 같은 길이의 바로 전 기간 수치를 나란히 보이고, Claude도 변화를 본다.
     - **저장:** 만든 시점의 통계와 Claude 해설을 저장하고 목록으로 다시 연다.
     - **Claude 해설(요청 시):**
       - 보내는 것: 통계, 묶음표, 원칙, 이전 기간 비교, 손익 상·하위 각 10건의 요약(종목·시각·손익·태그·원칙 어김), 그 거래들의 본인 메모(체결 후 작성 표시).
       - 그림 이미지는 보내지 않는다.
       - 형태: 요약 / 반복되는 실수 / 잘된 점 / 다음 기간에 집중할 것 / 원칙 변경 제안(추가·수정·삭제, 각각 근거 수치와 함께).
       - 후속 질문을 할 수 있다(2b와 같은 방식). 기간 거래 목록을 묶음 조건으로 걸러 요약해 주는 읽기 전용 도구를 둔다(구현 시 제안, 미확정).
     - **원칙 제안 반영:** 제안마다 근거와 함께 보이고, 사용자가 고른 것만 원칙 편집기에 넣는다. 확인한 뒤 새 버전으로 저장한다.

- 규칙 빌더 확장 범위: 어떤 조건이 필요한지는 실제 전략을 몇 개 만들어 보고 정한다.
- 기능별 기본 모델(복기는 Sonnet, 보조지표는 Sonnet effort medium 임시 — 파일럿 뒤 확정).
- 차트 이미지 해상도·봉 개수, 매매 원칙 문서의 형식(자유 글 vs 항목).
- 대화 길이가 길어질 때 앞부분 요약 방식.

## 보조지표 만들기 구현 단계(2026-10-28 사용자 승인)

결정(2026-10-28 질의응답):

| 항목           | 결정                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 동작 확인      | 실행 오류(줄·칸, 미지원 함수)와 계산값 요약(마지막 값, 범위, 빈 값 비율, 신호 횟수)을 Claude에 돌려준다                                                |
| 자동 수정      | 요청 하나에 최대 5번. 그래도 안 되면 멈추고 마지막 오류를 보인다                                                                                       |
| 대상           | 새 지표 + 저장된 내 Pine 지표 고치기 + TradingView 코드 옮겨오기 + 내장 지표를 출발점으로 한 변형                                                      |
| 대화 저장      | 지표마다 저장. 다시 열면 이어서 요청하고, 어떤 요청으로 어떤 코드가 나왔는지 남긴다                                                                    |
| 보내는 것      | 지원 범위(함수·미지원 목록)와 편집기 현재 코드, 종목·주기·봉 개수. 차트 이미지는 사용자가 고를 때만                                                    |
| 보내지 않는 것 | 원본 봉 값(OHLCV), 계좌·키·기록 ID                                                                                                                     |
| 미리보기       | 현재 차트에 임시로 그린다. "적용"을 눌러야 지표로 저장되고, 이전 버전으로 되돌릴 수 있다                                                               |
| 기본 모델      | Anthropic API: `claude-sonnet-5-5` (effort medium, 임시). "Local Agent 개발·유지보수" 세션 배정(회신 #SIW-1, 가설). 설정에서 Opus·Haiku로 바꿀 수 있다 |
| 승급           | 5번 고쳐도 실패하면 "Opus로 다시 시도" 버튼(사용자가 누름). 자동 승급은 하지 않는다                                                                    |

단계:

1. **대화·생성·자동 수정·계산 요약·차트 미리보기·저장.** Pine 편집기 옆 대화 패널, 지표마다 대화 저장, 차트 임시 표시와 적용·되돌리기.
2. **기존 코드 출발점·차트 이미지.** 저장된 Pine 지표 고치기, TradingView 코드 옮겨오기(미지원 함수 대체), 내장 지표 변형, 선택 차트 이미지 첨부.

모델 파일럿(1단계 중, 예산 $1~2): 예시 요청 10개를 sonnet medium·sonnet high·opus medium으로 돌려 ① 5번 안에 오류 없이 실행 ② 계산 요약이 의도와 맞음(항상 0·전부 빈 값 아님) ③ 수정 횟수 ④ 걸린 시간 ⑤ 비용을 기록해 배정 세션에 보낸다. ①② 성공률이 높은 쪽, 차이가 1요청 이하면 빠르고 싼 쪽을 기본으로 한다. Sonnet이 Opus보다 2요청 이상 낮으면 기본을 Opus로 바꾼다.

API 주의(배정 회신): temperature·top_p·top_k와 강제 `tool_choice`, 프리필은 보내지 않는다. 대화는 뒤에만 덧붙이고 thinking 블록을 그대로 다시 보낸다. 고정 시스템 프롬프트(지원 범위)를 앞에 두고 캐시하며 바뀌는 값은 뒤에 둔다. server-side fallback `"default"`, 긴 응답은 스트리밍과 넉넉한 max_tokens.

다시 볼 조건: 파일럿 결과, 실제 사용에서 5번 안 실패가 20% 초과, 요청당 60초 초과가 잦음, 새 Sonnet·Opus 출시.
