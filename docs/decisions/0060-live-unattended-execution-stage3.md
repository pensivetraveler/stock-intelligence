# ADR 0060 — SIW Agent 단계 3: 실계좌 한도 안 무인 실행 (초안)

- **Status:** proposed (초안). 2026-11-23 사용자가 "조건 달아 단계 3 ADR 초안"을 골랐다. [ADR 0047](0047-live-orders-per-order-confirmation.md)(실계좌 주문마다 승인)은 그대로 유효하다. 아래 "열기 조건"을 모두 채운 뒤 사용자가 다시 확정해야 accepted가 되고, 그 전에는 코드로 옮기지 않는다.
- **Date:** 2026-11-23
- **Related:** [ADR 0036](0036-desktop-app-roles.md)(주문 Gate 단계 3 "실계좌, 한도 안 자동"), [ADR 0047](0047-live-orders-per-order-confirmation.md)(단계 2), [ADR 0044](0044-paper-protective-orders.md)(보호 청산), [ADR 0057](0057-selection-flow-seven-stages.md)(7단계 흐름, 6단계 전략 틀), [ADR 0059](0059-market-hours-collectors-on-mini-pc.md)(장중 상주 장비)

## Context

- ADR 0057 7단계에서 사용자는 "향후 실계좌 무인 실행을 원함"이라고 했다. 미국 장이 한국 새벽이라 종목마다 승인할 수 없다는 사정(ADR 0057 Context)이 이유다.
- ADR 0047은 실계좌 주문을 주문마다 60초 안에 승인해야 내고, 보호 청산(손절·익절·트레일링)도 승인을 받는다. 자리를 비우면 진입도 손절도 나가지 않는다.
- 단계 1(모의) 운영 기록은 아직 짧고, 단계 2의 첫 실주문(ADR 0047 L3)도 아직 없다. 장중 기록 장비도 옮기는 중이다(ADR 0059).
- 그래서 2026-11-23 대시보드 항목 133을 물었을 때 사용자는 0047을 바로 바꾸지 않고, 조건을 단 초안을 남기기로 했다.

**2026-11-23 사용자 답(원문 선택지):**

1. 방향: "조건 달아 단계 3 ADR 초안"(다른 선택지: 손절·익절만 무인 먼저, 보류).
2. 열기 조건: "모의 무인 5거래일"(사용자 기타 답, 제안은 20거래일), "실계좌 승인 운영 기록", "앱 안 확인 경로", "장중 상주 장비".
3. 손실 한도: "하루 $100 / 주 $300".
4. 노출 한도: "3종목·총 $5,000".
5. 시작 규모: "처음 10거래일 25%".

## Decision (초안)

### 1. 열기 조건 — 모두 채워야 단계 3을 다시 확정할 수 있다

| 조건             | 내용                                                                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 모의 무인 운영   | 같은 7단계 흐름을 키움 모의투자로 **5거래일** 무인 운영. 그 기간 주문·체결 대조 불일치와 보호 청산 누락이 0건.                                        |
| 실계좌 승인 운영 | ADR 0047 방식(주문마다 승인)으로 실계좌 체결을 **최소 10건** 내고, 실전 응답 형식·체결 시각·조회 전용 동기화(ADR 0029)를 확인.                        |
| 앱 안 확인 경로  | 출처 헤더(로컬 프로세스가 꾸밀 수 있음, ADR 0037 §6) 대신, SIW Agent 안에서만 무인 실행을 무장할 수 있는 경로. ADR 0047 "Revisit when"의 요구와 같다. |
| 장중 상주 장비   | 미니PC처럼 장중 꺼지지 않는 장비에서 실행기가 돈다(ADR 0059). 실행기가 멈추면 보호 청산도 멈추기 때문이다.                                            |

### 2. 무인일 때 바뀌는 것 (0047 대비)

- 한도 안의 진입과 보호 청산을 승인 없이 낸다. 판단·한도·킬 스위치·대조는 지금 실행기(`PaperRunner` 공용, ADR 0047 §1)를 그대로 쓴다.
- 원장·도메인 분리(`live_orders.sqlite3`, `services/live_trading/`), 지정가만, 실전 키 1개 규칙은 그대로다.

### 3. 한도

| 한도        | 값                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------- |
| 하루 손실   | **$100**(실현 + 평가). 닿으면 킬 스위치를 자동으로 켜 새 진입을 멈춘다. 보호 청산은 계속 낸다.                |
| 주 손실     | **$300**. 닿으면 같은 방식으로 멈추고, 사용자가 풀 때까지 다시 열지 않는다.                                   |
| 동시 노출   | 보유·미체결이 있는 종목 **3개**, 매수 금액 합계 **$5,000**. 넘으면 새 매수를 내지 않는다.                     |
| 종목당 노출 | ADR 0057 6단계: 눌림·돌파 각 1건, 틀당 $1,000(보수적 $500), 최대 $2,000.                                      |
| 시작 규모   | 무인을 연 뒤 처음 **10거래일은 25%**(틀당 $250, 보수적 $125). 한도·대조 문제가 없으면 사용자가 100%로 올린다. |

### 4. 열 때 정할 것 (이번에 묻지 않음)

- 하루 주문 수 한도(0047은 2건). 무인이면 종목당 매수 2건과 분할 익절·트레일링·당일 청산 매도가 있어 다시 정해야 한다.
- 실행기 heartbeat가 끊기거나 원장 대조가 어긋날 때 자동으로 킬 스위치를 켤지.
- 정규장 밖 주문: ADR 0057의 당일 청산 시각은 애프터마켓 19:50 ET인데, 0047은 실계좌 장외 주문을 열지 않았다.
- 손실 한도의 평가 손실을 어떤 가격(확정 1분봉 종가 등)으로 계산할지.

## Alternatives

- **0047을 지금 개정해 무인 확정:** 단계 1·2 운영 기록이 거의 없어 고르지 않았다.
- **손절·익절만 무인 먼저:** 자리를 비워도 손절은 나가지만 진입은 여전히 승인이 필요해 새벽 흐름이 돌지 않는다. 사용자가 고르지 않았다.
- **보류(아무것도 기록하지 않음):** 열기 조건을 미리 정해 두지 않으면 모의 운영에서 무엇을 확인할지 정해지지 않는다.

## Consequences

- 지금 코드와 동작은 바뀌지 않는다. 실계좌는 계속 주문마다 승인이다.
- 모의 운영(ADR 0057 U-e 이후)에서 5거래일 무인 기록, 대조 불일치·보호 청산 누락 수를 남겨야 이 조건을 판단할 수 있다.
- 하루 손실 $100은 100% 규모에서 눌림 손절 한 번(틀 $1,000 × 8% = $80)과 조금 더에 해당한다. 나쁜 날에는 한두 종목 뒤에 멈춘다. 25% 규모에서는 손절 약 5번이다.
- 동시 노출 합계 $5,000이 3종목 × $2,000($6,000)보다 작아서, 세 종목 모두 두 틀이 체결되는 날에는 합계 한도가 먼저 걸린다.

## Revisit when

- 열기 조건 네 가지를 채웠을 때(이때 사용자 확정을 다시 받는다). 조건별 충족 현황은 [실계좌 주문 런북](../runbooks/live-orders.md) §5에서 갱신한다.
- 모의 무인 운영에서 대조 불일치나 보호 청산 누락이 나왔을 때.
- 손실 한도가 너무 자주(또는 한 번도) 걸릴 때.
