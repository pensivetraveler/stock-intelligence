# ADR 0057 — 종목 선정에서 SIW Agent까지 7단계 흐름

- **Status:** accepted(흐름). 2026-11-12 사용자가 1~7단계 흐름을 확정했다. 각 단계의 구현은 사용자 승인 뒤에 한다. "별도 논의"로 남은 항목은 아래 "사용자가 정할 것"에 있다.
- **Date:** 2026-11-12
- **Supersedes:** [ADR 0054](0054-selection-to-agent-scenario.md)의 1·2·3단계 구성, §1 움직임 예상 분류, §2 실시간 수급, U1~U6. 0054의 참고 문서, 사용자 결정(11-09·11-10), §3 공매도 자료는 그대로 유효하다.
- **Related:** [ADR 0052](0052-daily-candidate-screening.md)(당일 후보 스크리닝 A·B·C·D), [ADR 0053](0053-off-exchange-price-structure-model.md)(장외 체결 가격 구조), [ADR 0055](0055-intraday-momentum-candidates.md)(U0 모멘텀 수집), [ADR 0036](0036-desktop-app-roles.md)·[ADR 0037](0037-paper-order-execution.md)(모의투자), [ADR 0047](0047-live-orders-per-order-confirmation.md)(실계좌 주문마다 승인)

## Context

2026-11-10~12 사용자와 선정 방법을 논의했다. 출발점은 사용자의 이 관찰이다.

> "우선 종목선정 프로세스와 매수매도 전략 수립 프로세스 시 사용하는 팩터가 혼재되었어."

사용자가 정리한 각 팩터의 성격은 다음과 같다(원문).

- 진입조건(A): "매수매도 전략에 따라 탈락 혹은 완화 여부가 달라짐. 고정 조건이 아님."
- 장외 체결(D): "고른 뒤 가격을 잡는데 사용. 선정의 요건이 아님"
- 공매도: "스퀴즈 가능성 및 매도 압력. 스퀴즈 가능성은 종목 선정 요건이고, 매도 압력은 매수매도 전략". 스퀴즈 가능성은 "공매도 잔고 비율, 대차 가능 수량 고갈, 대차 이용률 등"으로 보고, "스퀴즈 가능성이 낮다고 하여 탈락되지 않음. 다른 요건과 함께 보는 가중치"다.
- 희석(C): "매수매도 전략에서, 어떤 가격대에서 매도 압력이 가중될 것인지를 확인하기 위한 팩터. 그와 함께 유통주식수에 대한 별도 측정에 활용"
- 뉴스(B): "재료가 없는 급등의 경우, 재료가 있는 급등에 비해 보수적 관점으로 매수매도 전략을 수립. 가령 목표 수익률을 낮추던가 하는 등. 그와 함께 … 급등 영향력이 낮은 재료인 경우에 대한 종목 매수 필터링"

사용자의 역할도 정했다.

> "사용자가 확정하는건 1~7단계의 흐름에 대한 확정만이야. 매 종목마다 스크립트를 확정하지 않아. 미국 장 시간이 새벽이라 나는 잠들어야 하고 매 종목을 모니터링할 수가 없어."

따라서 ADR 0054·0052의 "사용자가 고른 종목"은 더 이상 맞지 않는다. 종목은 시스템이 흐름에 따라 정한다.

## Decision

### 흐름

| 단계 | 내용                                                    | 탈락의 뜻                                                   |
| ---- | ------------------------------------------------------- | ----------------------------------------------------------- |
| 1    | 실시간 검색으로 모멘텀이 확인된 종목 수집               | 거르지 않음                                                 |
| 2    | 재료가 있을 때 재료의 영향력 분석                       | 그날 매매 대상에서 제외                                     |
| 3    | 실시간 수급(2단계 통과 종목)                            | **지금 시점**의 매매 대상에서 제외. 기준을 넘으면 다시 대상 |
| 4    | 희석, 장외 체결, 공매도(스퀴즈 가능성·매도 압력)        | 없음. 정보를 만드는 단계                                    |
| 5    | 차트 모니터링. 4단계까지의 정보로 예상 매수·매도 가격대 | 없음                                                        |
| 6    | 매수·매도 스크립트 확정                                 | 없음                                                        |
| 7    | SIW Agent로 넘김                                        | 키움 모의투자로 자동 실행                                   |

### 1단계 — 모멘텀 종목 수집

- "1단계는 실시간 검색을 통한 모멘텀 확인이 된 종목들의 수집이야."
- 키움 실시간 조건검색 `SIW_당일급등주`의 편입을 모멘텀으로 본다. 기존 U0(ADR 0055)와 기록기(ADR 0051)를 그대로 쓴다. 조건식 내용은 아직 확인하지 않았다.

### 2단계 — 재료 영향력

- "2단계는 해당 종목들이 재료가 있을 때, 재료에 대한 영향력 분석이야."
- **판정:** NIR(news-analysis 서비스의 기사별 LLM 기록)로 판정한다. NIR이 없을 때(비용 상한, 서비스 꺼짐)는 규칙으로 판정한다.
- **판정할 수 없을 때:** 통과시키고 "재료 미확인"으로 표시한다.
- **통과:** 저영향이 아닌 재료가 하나라도 있으면 통과한다.
- **재료가 없을 때:** 통과한다. 이후 전략을 보수적으로 세운다. 방식은 5단계 가격대 규칙과 함께 정한다.
- **저영향 재료 목록은 이 ADR에서 정하지 않는다.** 사용자: "이런건 너랑 함께 논의를 해야해. 가령 rdo 의 경우 오퍼링 완료는 해당 오퍼링 전환가격이 anchoring이 되는 경우이고 이 경우 주가가 오르는 경우가 존재해. NIR의 저영향 규칙이 무엇무엇인지는 여기서 정하지는 말자." 지금까지 나온 예시는 다음과 같다. 예시일 뿐 규칙이 아니다.
  - 공모(public offering) 신청·발표. 완료는 제외한다.
  - Nasdaq 상장폐지 요건 회복
  - "어닝 시즌에서 규모 자체는 크지 않은, 단순 %로만 환산된 매출 증가 강조 뉴스"
  - "전임상 및 1상 뉴스"
- **LLM을 여기서 쓰는 이유:** 사용자: "NIR은 그에 비해 토큰이 상대적으로 많이 안쓰이기 때문이야. 그리고 뉴스는 맥락이 너무 다양하기 때문에 그걸 규칙화하는게 무의미해." NIR의 모델·비용 상한은 ADR 0054의 2026-11-10 결정을 따른다.

### 3단계 — 실시간 수급

- 대상: 2단계를 통과한 종목. 장 마감까지 감시한다.
- 방식: "스크립트로 직접 감시하는 방향으로 하자". 키움 조건식(`SIW_실시간수급`)은 쓰지 않는다.
- 목적: "실시간으로 거래대금이 얼마나 유통되고 있는지를 확인하기 위함이야. 최소 몇백만원 수준으로는 거래가 되어야 한다고 보고 있어." 조건3은 "변동성이 존재하는가"를 본다. 대상은 "저가주 위주"다.
- 1분봉이 닫힐 때마다 지금 시점에서 거꾸로 센다("5봉과 20봉의 창은 지금시점에서 거꾸로 세"). 평균 대신 "N봉 이상" 방식을 쓴다(사용자: "평균의 함정은 피하고 싶지").

| 조건   | 내용                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------- |
| 유동성 | 최근 5봉 중 **4봉 이상**이 "거래대금 ≥ $5,000 **그리고** 거래량 ≥ 1,000주"                      |
| 변동성 | 최근 20봉 중 "\|종가 − 시가\| / 시가 ≥ 1% **그리고** 2호가 이상"인 봉이 **3개 이상**(방향 무관) |

- 숫자는 확정이다("거래대금 $5,000과 거래량 1,000주 : 확정."). 거래대금을 위주로 보되 "최소한에 거래량은 존재해야해".
- 빈 분(체결 없는 1분)은 미달 봉으로 센다.
- halt 중의 빈 분은 세지 않는다("halt 중 빈 분은 세지 않는 쪽으로"). halt 구간은 창에서 빼고 그 앞의 봉으로 창을 채운다.
- 호가 잔량은 조건에서 뺀다("호가 잔량은 조건에서 제외하자.").
- 호가 단위는 $1 이상이면 $0.01, $1 미만이면 $0.0001이다. "2호가"는 이 단위의 2배다.
- 조건3의 원문 "-1%이상"은 "-1% 이하가 맞아"로 정정했다.
- **halt 감지(2026-11-12 확인, 아래 "U-a 구현"):** Alpaca SIP 실시간 스트림의 `statuses` 채널. 이 계정에서 받는 것은 실측했다. 과거 halt를 돌려주는 REST는 문서에 없다. 기록기는 아직 없어서 지금은 halt 중의 빈 분도 미달로 센다(사용자 결정 대기).

### 4단계 — 정보 만들기

- 시점: 2단계를 통과하면 바로 돌린다("2단계 이후").
- 내용: 희석, 장외 체결, 공매도(스퀴즈 가능성·매도 압력). 아무것도 탈락시키지 않는다("정보 만드는 단계").
- **LLM을 쓰지 않는다.** 사용자: "종목 선정 프로세스에서는 LLM을 사용하지 않고, 세워진 규칙 하에 분석." 이유: "4단계 희석은 분석에 너무 많은 토큰이 소요되기 때문이고". 희석은 규칙만(`llm=false`)으로 요청한다.
- 공매도: "공매도 자료가 없는 동안에는 공매도 없이 시행". 자료 출처는 ADR 0054 §3(유료 API, 사용자 선택)을 따른다.

### 5단계 — 차트 모니터링과 가격대

- "5 단계는 정확하게는 차트를 모니터링 하는 단계야. 4단계까지의 정보를 토대로 예상 매수/매도 가격대를 선정해."
- 가격대는 "시스템이 설정"하고, 사용자는 "차트를 보면서 장중에 수정 가능"하다.
- **가격대 규칙은 별도 논의다.** 재료가 없을 때 "보수적으로"의 구체적 방식도 같이 정한다.

### 6단계 — 매수·매도 스크립트

- "미리 정한 전략 틀에 종목의 가격대만 끼워넣기". 전략 틀의 개수와 내용은 별도 논의다.
- 5단계 가격대가 나온 뒤 확정한다. "장중에 가격대를 고치면 넘긴 스크립트도 변경되어야 함".
- 담는 것은 "진입 및 청산 가격대만 우선 고려"한다. 수량, 시간 제한, 종목 수 한도는 지금 정하지 않는다.
- **3단계에서 빠졌을 때:** "매수 취소하지 않음. 그대로 두기". 걸린 매수 주문과 가진 수량은 그대로 둔다. 빠진 동안 그 종목에 새 매수는 내지 않는다(사용자 확인 "맞음").

### 7단계 — SIW Agent

- "7단계에서 SIW Agent에 넘겨". 키움 모의투자로 자동 실행한다(ADR 0036·0037, "키움 모의투자 먼저").
- 사용자는 향후 **실계좌 무인 실행**을 원한다("향후 실계좌 무인 실행을 원함"). 이것은 ADR 0047(실계좌 주문마다 사용자 승인)을 바꾸는 별도 결정이며, 이 ADR은 실계좌 흐름을 바꾸지 않는다.

### 주 1회 검수 (흐름 밖)

- 사용자: "추가분석이 필요한건 종목선정 때 하는게 아니라, 특정 주기 별로 선정된 종목들에 대한 검수를 할 때 분석을 한다는걸 의미한거야."
- 주기: 주 1회.
- 대상: "그 주기 동안 3단계 매매 대상이 된 종목 전부".
- 쓰임: "규칙(조건값, 저영향 재료 목록)을 고치는 근거".
- 수단: 지금 정해진 것은 희석 LLM뿐이다. 나머지는 "결정이 되고 나서 다시 이야기하자. 아직 프로세스 전체가 다 완성이 안된 상태야."
- 주의: 희석 LLM 상한은 종목·날짜당 $0.15, 월 $10(약 90건)이다(ADR 0052 §4). 한 주의 3단계 대상이 많으면 상한에 닿을 수 있다.

### 폐기

- **움직임 예상 분류(ADR 0054 §1, U2):** "움직임 분류에 대한 건 폐기".
- **피보나치 되돌림 확인:** "피보나치 항목도 폐기".
- **진입조건 A(ADR 0052 §2):** "진입조건 A 자체는 매수매도 실행에서는 적용 안되는 이야기 같은데? 폐기하자". 구현된 코드(`services/screening/entry.py`, '오늘의 후보' 패널 열)를 어떻게 처리할지는 구현 단계에서 정한다.
- **희석 LLM을 사용자가 고른 종목에(ADR 0052 §4 "하루 2~3종목"):** 사용자가 종목을 고르지 않으므로 주 1회 검수로 옮긴다.

## U-a 구현 — 3단계 실시간 수급 감시 (2026-11-12)

- **계산:** `services/screening/flow_watch.py`(`flow-watch-1`, 규칙 `adr-0057-stage3-1`). 세션 시작(04:00 ET)부터 마지막으로 닫힌 1분까지의 분 격자를 만들고, 분마다 그 분과 그 앞의 분만으로 판정한다(미래 데이터 없음). 위 표의 숫자를 그대로 쓴다.
  - 분 하나는 봉, 빈 분, 모름 중 하나다. 공급자의 빈 분 이유 `provider_no_bar`·`not_yet_final`은 빈 분(체결 없음, 미달), `outside_entitlement`·`not_available_as_of_cutoff`는 모름이다. 창에 모름이 있으면 `unknown`(판정 불가)이다. `not_yet_final`이 창에 있으면 `provisional`로 표시한다(늦은 체결이 봉을 바꿀 수 있다).
  - 거래대금은 봉의 (고가+저가+종가)/3 × 거래량 추정치다(모멘텀 검사와 같음). 표준 봉에 VWAP가 없다.
  - 호가 단위는 봉의 시가로 정한다($1.00 이상 $0.01, 미만 $0.0001).
  - halt 구간과 겹친 빈 분은 창에서 빼고 더 앞의 분으로 채운다. halt 중에도 체결이 있는 분은 센다. halt가 지금 열려 있으면 상태는 `halted`.
  - 상태: `eligible`(대상), `excluded`(제외), `warming_up`(창이 아직 5분·20분이 안 됨), `unknown`, `halted`. 하루의 상태 변화(`changes`)와 대상이었던 분 수를 함께 낸다. 주 1회 검수의 근거다.
  - 주문 관련은 상태 값만이다: `new_buys_allowed`(대상일 때만 참), `resting_orders: "keep"`. 주문 기능은 없다.
  - 판정 시점: 분이 끝나고 20초 뒤(`SETTLE_SECONDS`). Alpaca가 분 집계를 내놓는 데 걸리는 시간은 재지 않았다(미확인).
- **halt 기록:** `services/screening/halts.py`가 상태 메시지를 halt 구간으로 바꾼다. 멈춤 코드는 CTA `2`, UTP `H`·`P`, 재개 코드는 CTA `3`, UTP `T`(`Q`는 호가만 재개라 아직 멈춤)다. 2026-11-12 09:14 ET 1분 실측(사용자 키, 읽기 전용, 저장 안 함): 구독이 받아들여졌고 CTA halt(`sc` `2`, tape B)가 5초마다 반복해 왔다. UTP 메시지는 그 1분에 오지 않아 UTP 코드는 문서 기준이다. LULD 메시지도 프리마켓이라 오지 않았다. **스트림을 듣는 기록기는 만들지 않았다**: 새 상시 프로세스이고 Alpaca SIP 스트림 연결 수 제한(계정당)에 걸릴 수 있어 사용자 결정이 필요하다. 그때까지 API는 `halts.available=false`와 경고를 낸다.
- **대상:** 오늘의 후보 전체(조건 기록 + 사용자가 넣은 종목). 2단계(U-b)가 없으므로 `stage2: "not_implemented"`. 판정이 생기면 `register_screening_flow_routes(stage2=...)`로 넣는다. `failed`면 `new_buys_allowed`가 거짓이 된다.
- **API:** `GET /v1/screening/flow?session_date=`(계약 `screening_flow_watch`). 저장하지 않고 부를 때마다 봉으로 다시 만든다. 후보 4개씩 동시에 읽는다.
- **패널:** '오늘의 후보'에 "지금 수급(3단계)" 열(상태 · 유동성 n/5 · 변동성 n/20). 1분마다 다시 읽는다. 정오 자르기 보기에서는 읽지 않는다.
- **실제 확인(2026-11-12 09:25 ET, 사용자 Alpaca 키, 조건 기록 복사본):** 오늘 후보 29개 중 12개 판정, 모두 `ok`, 대상 9·제외 3. 04:00부터 325분 판정.
- **남은 것:** halt 기록기(사용자 결정), U-b 연결, 판정 시점 여유(20초) 실측, 실제 앱에서 열 확인(SIW API 재시작 필요), 장 마감 기준이 정규장 마감인지 애프터마켓 끝인지(지금은 세션 창 끝 20:00 ET까지 판정).

## 구현 단위 (각 단계는 사용자 승인 뒤)

1. **3단계 수급 감시 스크립트:** Alpaca SIP 1분봉으로 위 두 조건을 장 마감까지 판정. halt 감지 방법 확인을 포함한다.
2. **2단계 재료 탈락 판정:** NIR 결과 → 통과·탈락·"재료 미확인". 규칙 대체 경로. 저영향 목록은 논의 뒤에 넣는다.
3. **4단계 자동 실행:** 2단계 통과 즉시 희석(규칙만)·장외 체결을 돌린다. 공매도는 자료가 생기면.
4. **진입조건 A 정리:** 기존 코드·패널 열 처리.
5. **5·6단계:** 가격대 규칙과 전략 틀이 정해진 뒤.
6. **7단계 모의투자 연결:** 스크립트를 SIW Agent 키움 모의투자로 넘기고, 장중 가격대 수정을 반영.
7. **주 1회 희석 LLM 검수.**
8. **나중에:** 3단계 조건 시뮬레이터와 외부 검토 모듈. 사용자: "먼저 스크립트 작성까지의 모든 과정을 끝낸 다음에, 조건 시뮬레이터 및 외부 검토 모듈을 달아보자."

## 사용자가 정할 것

- 저영향 재료 목록(NIR 규칙). 함께 논의.
- 5단계 가격대 규칙과 재료 없음일 때의 "보수적" 방식.
- 6단계 전략 틀의 개수와 내용.
- `SIW_당일급등주` 조건식 내용 확인.
- 실계좌 무인 실행(ADR 0047 변경).
- 주 1회 검수의 희석 LLM 외 수단.

## Alternatives

- **3단계를 키움 조건식(`SIW_실시간수급`)으로:** 사용자가 스크립트 직접 감시를 골랐다. 조건과 창을 코드로 확인하고 시뮬레이터로 되돌려 볼 수 있다. 키움 기록기 연결을 하나 더 쓰지 않는다.
- **평균 거래량·거래대금:** 한두 봉의 큰 체결이 평균을 끌어올린다. "N봉 중 M봉 이상"으로 바꿨다.
- **4단계에서도 LLM:** 희석 분석의 토큰 비용 때문에 쓰지 않는다. 검수로 옮겼다.
- **사용자가 종목마다 확정:** 미국 장이 한국 새벽이라 불가능하다는 사용자 사정으로 쓰지 않는다.

## Consequences

- 사용자가 종목마다 개입하지 않으므로, 흐름의 각 판정(2단계 탈락, 3단계 이탈·재진입, 가격대, 스크립트 변경)을 시각과 근거와 함께 남겨야 주 1회 검수에서 규칙을 고칠 수 있다.
- 2단계의 판정 불가는 통과로 처리한다. 뉴스 서비스가 꺼져도 흐름은 멈추지 않지만, "재료 미확인" 종목이 늘 수 있다.
- 3단계 이탈 중에도 걸린 매수는 남으므로, 수급이 약해진 뒤 체결될 수 있다. 사용자가 택한 동작이다.
- 5·6단계 규칙이 정해지기 전까지는 7단계로 넘길 스크립트가 없다.

## Revisit when

- 저영향 재료 목록, 가격대 규칙, 전략 틀이 정해졌을 때.
- 조건 시뮬레이터로 3단계 숫자를 되돌려 봤을 때.
- 공매도 공급업체를 골랐을 때.
- 실계좌 무인 실행을 결정할 때(ADR 0047).
