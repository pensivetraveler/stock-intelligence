# ADR 0056 — 매매기법 자료(영상·PDF)에서 규칙 빌더 전략까지

- **Status:** proposed(초안). 2026-11-09 사용자 요구와 결정을 옮겼다. 도서관 세션 회신(`[요청 #SIW-lib-1]`, 2026-11-09 받음 — 지금은 불가, §2)과 모델 배정 회신(`[요청 #SIW-lib-2]`, 2026-11-09 임시 배정 받음 — §5)을 받고 아래 "사용자가 정할 것"이 정해지기 전에는 구현하지 않는다.
- **Date:** 2026-11-09
- **Related:** [ADR 0042](0042-claude-assistants.md)(전략 연구: Pine strategy → 규칙 빌더 변환·비교), [ADR 0038](0038-price-level-strategies.md)(가격대 전략), [ADR 0021](0021-backtest-engine.md)(백테스트 엔진), [ADR 0032](0032-walk-forward.md)(워크포워드), [ADR 0036](0036-desktop-app-roles.md)(Research·Agent 역할), [ADR 0054](0054-selection-to-agent-scenario.md)(2단계 전략 적용)

## Context

- **사용자 요구(2026-11-09):** 매매기법을 다룬 영상(유튜브)이나 PDF를 SIW가 활용할 자료로 **도서관에 등록**하고, 그 내용을 토대로 **매수·매도 전략을 고안**하는 기능. 예시로 유튜브 영상 3개(재생목록 1개 포함)를 줬다.
- **도서관 쪽 사실(2026-11-09, knowledge-library 저장소 문서로 확인, 실행해 보지는 않음):**
  - 등록 도구는 이미 있다. Commonplace(`cpl`, 옛 youtube-diary)가 유튜브 자막·메타데이터를 받아 노트를 만들고 요약한다(외부 모델 `#yd-2` 배정). PDF는 요약하지 않고 원본·쪽수만 남긴다. 글자 추출(문자 인식 포함)은 도서관 몫인데 아직 없다.
  - 노트는 사용자가 서명한 내보내기(`kl-yd-ingest/1`)로만 도서관에 들어간다.
  - 도서관은 영상에서 온 자료(도메인 yd-third-party: 자막·요약·AI 해석)를 **격리**해 검색에 내주지 않는다. 지금 검색되는 것은 사용자 메모·감상(yd-own)뿐이다.
  - 도서관 MCP는 Claude Code 세션용이고, 호출자는 실행 OS 계정 바인딩으로 정해진다. 앱(SIW Research)이 직접 부르는 경로는 정해진 것이 없다.
  - 받은 원문은 `context hydrate`로만 받고, 다시 쓰기 전마다 `hydration-check`를 부른다. 요약·AI 해석은 늘 `unverified`다.
- **SIW 쪽 사실:** 전략 연구(ADR 0042 1~3단계 구현)가 Claude 대화로 Pine strategy 초안을 만들고, 사용자가 백테스트를 실행하고, 확정 시 규칙 빌더 전략으로 변환·나란히 비교한다. 변환 저장은 코드로 된 조건을 모두 통과해야 열린다.

## 사용자 결정(2026-11-09 질의응답)

| 항목      | 결정                                                                                     |
| --------- | ---------------------------------------------------------------------------------------- |
| 자료 경로 | **도서관 경유.** `cpl`로 등록 → 도서관 → SIW가 조회. 도서관 쪽 변경은 도서관 세션에 요청 |
| 산출물    | **규칙 빌더 전략까지.** 기법 카드 → Pine strategy → 규칙 빌더 변환을 한 흐름으로         |
| 사용 위치 | **SIW Research 앱 화면.** 자료 목록에서 골라 "전략 고안" → 전략 연구 패널로 이어짐       |
| 전략 순서 | **규칙 빌더 먼저**(2026-11-13). 카드 → 규칙 빌더 JSON → Pine은 템플릿으로(§4)            |

## Decision (초안)

### 1. 흐름

```
[사용자] 영상 URL·PDF ──cpl add──▶ Commonplace 노트 ──서명 내보내기──▶ 도서관(매매기법 자료)
                                                                          │ 조회(§2, 도서관 회신 대기)
SIW Research "기법 자료" 목록 ◀────────────────────────────────────────────┘
   │ 사용자가 자료 선택 → "전략 고안"
   ▼
① 기법 카드(근거 인용) ─▶ ② 사용자가 카드 검토·모호한 점 답함 ─▶ ③ 규칙 빌더 전략 초안(JSON, 스키마 검증)
   ─▶ ④ 사용자가 백테스트 실행 ─▶ ⑤ Pine 템플릿 생성(TradingView 대조용)·나란히 비교 ─▶ ⑥ 사용자가 저장(버전)
```

- 각 화살표의 실행·저장은 사용자가 누른다. 주문·SIW Agent 배포는 이 흐름에 없다(배포는 ADR 0036·0054의 기존 절차).

### 2. 자료 조회 — 도서관 회신 `[회신 #SIW-lib-1]` (2026-11-09, knowledge-library `c538288`, 등록부 KL-REG-01 r3, 도서관이 문서·코드로 답함, 실행 확인 없음)

**지금은 불가.** 사용자(Owner) 결정 두 건과 도서관 구현 두 건이 먼저다.

| 질문                    | 도서관 답                                                                                                                                                                                                                                                                                                                                                                                                    | 막는 것                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 근거로 읽기             | 자막·웹 본문·PDF 원본과 그 요약·AI 해석·metadata는 모두 yd-third-party(권리 미확인·격리·목적 없음)라 검색·Hydration·AI 전송이 BLOCK. 여는 방법 (a) 계약 0.4.4 후보 "권리 미확인 자료 사용 규칙"으로 yd-third-party 전체에 `project_work` 검색·Hydration을 연다, (b) **매매기법 자료용 새 도메인**을 만들어 그 범위만 연다. 도서관 추천은 (b)(범위가 작고 다른 제3자 자료로 번지지 않음, 설계 채널 판정 거침) | 사용자 결정 + Owner 서명(등록부 r4)                      |
| PDF 글자 추출           | 도서관 몫(2026-11-04 결정)이지만 코드·WBS 항목 없음. 일정 없음. 문자 층 있는 PDF 먼저, 스캔본 문자 인식은 뒤로 제안 예정                                                                                                                                                                                                                                                                                     | 사용자 결정(대시보드 `knowledge-library-113`)            |
| 호출 경로               | **`python -I -m kl.cli …`.** 같은 OS 계정 프로세스는 바인딩상 세션 Principal이라 SIW Python API 프로세스도 해당. stdout 봉투 JSON 하나, 종료 코드 0 ≠ eligible이라 봉투를 판정. 원문은 `hydrate --out-dir`로 파일(0600, 덮어쓰지 않음). Task는 purpose `project_work`로 등록. MCP는 stdio 세션용, 내보내기 파일은 수용 입력이라 읽기 경로가 아님                                                             | 없음                                                     |
| 매매기법 구분           | 내보내기 형식 `kl-yd-ingest/1`에 태그·카테고리가 실리지 않음. 형식에 사용자 확정 태그·카테고리(AI 후보 제외)를 싣는 변경 필요(Commonplace 작업은 작음, 형식 버전은 도서관이 정함, 감사 대상). 그동안 `cpl tag <ID> --add <고정 태그>`로 붙여 둠                                                                                                                                                              | 사용자 결정(`knowledge-library-115`), 태그 이름은 사용자 |
| 로컬 캐시 + 매번 재확인 | 원칙상 맞음(`recall_guarantee=none`). 캐시는 0600·저장소 밖, `stop_using`·격리 시 **캐시 삭제와 카드 근거 철회**까지. 최종 확인은 (a)/(b) 사용 규칙이 정해질 때                                                                                                                                                                                                                                              | (a)/(b)                                                  |

- **사용자 결정(2026-11-09):** 전용 도메인(b)이 아니라 **태그·카테고리 기반**으로 한다. 도서관 자료는 태그·카테고리로 나누고, 그 태그에 따라 참고할 만한 다른 세션에 공유하는 것이 도서관의 모토다. 도서관이 그렇게 정의돼 있지 않다면 도서관 설계 오류로 보고, 도서관 세션이 사용자와 함께 파악·수정한다(`[요청 #SIW-lib-3]`, 회신 대기). SIW는 매매기법 태그가 붙은 자료를 조회하는 쪽으로 L1을 설계한다.
- **도서관 회신 `[회신 #SIW-lib-3]`(2026-11-09, knowledge-library `01c732d` `docs/decisions/2026-11-09-shared-library-no-silos.md`):** 도서관이 사용자와 진단해 하나의 공유 공간으로 재설계하기로 했다. 기본 열림(사용자 세션 모두 같은 도서관), 권리 여부로 막지 않음(사용자 결정), 카테고리·태그로 나누고 태그를 구독한 세션에 새 자료를 제안. 출처·계보, 미검증 표시, 정정 전파, 키·토큰·개인정보 배제, 외부 모델 전송 데이터 등급 규칙은 남는다. 위 표의 (a)/(b) 선택지는 없어졌고 경로(`kl.cli` + 봉투 판정)와 캐시 규칙은 그대로다. **아직 아님:** 계약·등록부·수용 형식 변경 → 설계 채널 판정 → Owner 서명 → 구현. 태그 이름과 태그 구독 명령 모양은 도서관이 다시 안내한다. PDF 글자 추출은 별도 결정 대기(`knowledge-library-113`). 그때까지 L1은 보류한다.
- **도서관 0.5.0 전환 안내 `[안내 #kl-m2]`(2026-11-12) 와 확인:** 도메인이 `library` 하나로 합쳐졌고(등록부 KL-REG-01 r4 서명·설치), 영상 자막 같은 제3자 자료도 `search`·`context hydrate`에 나온다(미검증은 `conditional`, 결과마다 `verification_status`·`source_authenticity_status`·`data_grade`(지금 모두 private)·`rights_status`·`pending_correction`). 태그 거르기·태그 구독은 M3·M4 뒤(지금 `DEFERRED`). 2026-11-12 이 세션에서 확인한 것:
  - `python -I -m kl.cli task register`(purpose `project_work`, library 도메인)는 성공했다. 같은 요청을 이 세션의 도서관 MCP 도구로 보내면 `NOT_AVAILABLE`이었다(MCP 프로세스가 전환 전 등록부를 보는 것으로 추정, 도서관 세션에 알림).
  - `kl.cli search` "매매"는 1건(`conditional`·unverified·private). 예시 영상 3개의 영상 ID로는 보이는 범위에서 못 찾음 — 아직 `cpl`로 등록되지 않은 것으로 보인다(L0는 사용자 몫).
- **영상 시각 인용(보충 회신):** 자막 층(`transcript`)은 줄마다 `[mm:ss] 문장`(1시간 넘으면 `[h:mm:ss]`), 큐 시작 초 단위(끝 시각·밀리초 없음). 인용 근거는 자막 층을 원본으로 한다. AI 요약 속 시각은 자막에서 온 것만 쓴다. 인용 대조 스크립트는 큐 시작 시각과 앞뒤 큐 하나를 본다.
- SIW 쪽 규칙: 받은 원문은 저장소 밖 로컬 캐시(0600)에만 두고, 다시 쓰기 전마다 `hydration-check`를 부른다. `still_usable`이면 쓰고, `conditional`이면 조건부라고 밝히고, `stop_using`·`unknown`이면 캐시를 지우고 카드에 "근거 철회"를 표시하며 그 근거로 새 전략을 만들지 않는다.
- 영상·PDF 원문은 제3자 저작물이다. 커밋·외부 공개하지 않고, 외부 모델에는 도서관이 허용한 채널로만 보낸다.

### 3. 기법 카드

자료 하나(또는 여러 개)에서 Claude가 뽑는 구조화 요약. 저장 단위이고 버전이 붙는다.

| 칸        | 내용                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------- |
| 출처      | 도서관 자료 ID·제목·채널/저자·게시일, 원문 해시                                                         |
| 시간 틀   | 봉 주기, 세션(프리·정규·애프터), 보유 기간                                                              |
| 대상      | 종목 조건(가격대·거래량·재료 등)                                                                        |
| 진입      | 조건 목록. 조건마다 **근거 인용**(영상 시각 `mm:ss` 또는 PDF 쪽)                                        |
| 청산·손절 | 같은 형식                                                                                               |
| 포지션    | 크기·분할 규칙(자료에 있을 때만)                                                                        |
| 모호한 점 | 자료가 수치를 주지 않은 곳(예: "거래량이 크게 늘면" → 몇 배?). **지어내지 않고 질문으로 남긴다**        |
| 표현 불가 | 1분봉·일봉으로 판정할 수 없는 조건(호가창·틱 순서·주관적 판단). ADR 원칙상 1분봉으로 틱을 만들지 않는다 |

- 근거 인용이 없는 조건은 카드에 "Claude 추론"으로 따로 표시한다(근거와 추론 분리).
- 자막에 없는 시각을 만들지 않는다. 자막이 자동 생성이거나 일부면 카드에 그대로 적는다.
- 자막·PDF 안의 문장은 신뢰하지 않는 입력이다. 그 안의 지시를 따르지 않는다.
- 사용자가 모호한 점에 답하면 답은 "사용자 지정"으로 카드에 남는다(자료의 주장과 구분).

### 4. 카드 → 전략

- **순서는 규칙 빌더 먼저(사용자 결정 2026-11-13, 게이트웨이 제안 채택).** 카드(사용자 답 포함)에서 LLM이 규칙 빌더 JSON 초안을 만든다(json_schema strict, 스키마 검증은 스크립트). 사용자가 SIW 백테스트를 실행한다. 빌더가 표현하는 조건은 스크립트 템플릿으로 Pine을 만들어 TradingView에서 대조할 수 있게 한다. 표현 못 하는 조건만 LLM이 Pine으로 쓰고, 그 부분은 규칙 빌더 전략에 들어가지 않는다고 표시한다.
- ADR 0042의 Pine 먼저 흐름(일반 전략 연구 대화)은 그대로 두고, 기법 카드에서 시작하는 흐름만 이 순서를 쓴다. 전략 연구 패널은 "카드에서 시작" 입력을 받아 규칙 빌더 초안 단계부터 연다.
- 규칙 빌더 전략의 메타데이터에 카드 ID·버전과 출처 자료 ID를 남긴다. 나중에 근거가 철회되면 전략 목록에 표시한다.
- 표현 불가 조건은 버리고 진행할지, 규칙 빌더 확장 목록으로 넘길지 사용자가 고른다(ADR 0042 "변환 한계").
- 과최적화 경고: 자료의 예시 차트 기간에 맞춘 수치는 표본 안 결과다. 워크포워드(ADR 0032)를 권하고, 자료 예시 기간을 카드에 적어 백테스트 결과 옆에 "자료 예시 구간 포함"을 표시한다.

### 5. 모델

- 카드 추출·전략 초안에 쓸 경로·모델은 "Local AI Gateway 개발·유지보수" 세션에 `[요청 #SIW-lib-2] 모델 배정`으로 받는다. 회신을 여기에 적고 사용자 확정을 받는다. 스크립트로 할 수 있는 부분(자막 시각 정렬, 인용 대조, 형식 검사)은 스크립트로 한다.
- 인용 대조는 스크립트로 한다: 카드의 인용 문구가 받은 원문의 그 시각·쪽에 실제로 있는지 확인하고, 없으면 그 조건을 "근거 불일치"로 표시한다.

- **확정 조건:** 실제 자료 5~10건(자막·PDF 섞어)에 정답 카드를 붙인 평가 세트를 SIW가 만들어 파일 경로만 보낸다(원문은 보내지 않음, 형식은 local-ai-gateway `docs/MODEL_ASSIGNMENT.md` models eval + `responseSchema`). 게이트웨이가 sonnet·luna·haiku를 비교한다.

#### 평가 세트 구성 (사용자 결정 2026-11-13)

정답 카드(사람이 맞다고 정한 기준 카드)를 사람이 처음부터 쓰지 않도록 두 가지로 만든다.

- **공개 코드가 있는 기법(실제 자료):** 영상·PDF와 함께 작성자가 TradingView 공개 스크립트(Pine)를 낸 기법을 고른다. 정답 카드의 진입·청산·손절 조건은 그 코드에서 옮기고, 인용(영상 시각·PDF 쪽)과 코드에 없는 모호한 점만 사람이 확인한다. 자료는 L0처럼 사용자가 `cpl`로 등록한다. 원본 코드·자막은 저장소에 넣지 않고 로컬 평가에만 쓴다.
- **합성 자료:** 이미 있는 규칙 빌더 전략에서 시작해, 그 규칙을 말로 설명하는 자막(`[mm:ss]` 줄)을 만든다. 정답 카드는 원래 규칙이다. 일부러 넣은 모호한 표현·규칙으로 만들 수 없는 말·잡담이 카드의 "모호한 점"·"표현 불가"로 가는지, 지어낸 조건이 없는지, 인용 시각이 맞는지를 본다. 권리 문제가 없어 저장소 픽스처로 둘 수 있다.
- 합성 자료는 실제 자막의 말투·군더더기를 재현하지 못하므로 "실제 자료 5~10건" 조건을 공개 코드 기법으로 채우고, 합성은 지어낸 조건·인용 검사를 더하는 보조로 쓴다. 이 구성이 확정 조건을 채우는지는 게이트웨이 회신을 받는다(`[요청 #SIW-lib-4]`).
- **공개 코드 기법 후보(2026-11-13 조사, 내용 미확인):** GitHub `jayadevrana/free-pine-script-indicators`(MPL-2.0)는 전략마다 Pine v6 코드와 설명 영상을 짝지어 둔다. 전략(strategy) 7개 중 6개를 후보로 둔다.

  | 전략                               | 영상                         | 코드                                                  |
  | ---------------------------------- | ---------------------------- | ----------------------------------------------------- |
  | My First Strategy                  | https://youtu.be/at8brpnawyE | `scripts/first-strategy.pine.txt`                     |
  | EMA Trend Strategy                 | https://youtu.be/hWeaFBH0lbk | `scripts/ema-trend-strategy.pine.txt`                 |
  | Risk Managed Strategy              | https://youtu.be/MXxL8ZLBYms | `scripts/risk-strategy.pine.txt`                      |
  | Larry Williams Volatility Breakout | https://youtu.be/KxJ5f8lWWfY | `scripts/larry-williams-volatility-breakout.pine.txt` |
  | Turtle Trading Rules               | https://youtu.be/Q81ywGllmhg | `scripts/turtle-trading-rules.pine.txt`               |
  | Linda Raschke Holy Grail           | https://youtu.be/sqxkyZabuzw | `scripts/linda-raschke-holy-grail.pine.txt`           |
  - 빼는 것: "Booming Bulls Sniper"는 다른 사람의 기법을 이 작성자가 해석해 코드로 옮긴 것이라 영상과 코드의 작성자가 다르다.
  - 한계: 코딩 강의라 규칙을 명시적으로 말하므로 실제 기법 영상(사용자 예시 3개)보다 쉽다. 영상에서 말한 수치와 코드의 최적화 수치가 다를 수 있어, 정답 카드는 영상에서 말한 내용을 기준으로 하고 코드는 대조용으로 쓴다. 둘이 다른 곳은 사람이 확인한다.
  - 영상 자막은 아직 받지 않았다. 사용자가 `cpl`로 등록해야 도서관을 거쳐 쓸 수 있다.

#### 평가 세트 회신 `[회신 #SIW-lib-4]` (2026-11-13, Local AI Gateway 세션)

- **충분하다(자막 경로 확정용).** 실제 자료는 공개 코드 기법 5건 이상, 보조로 합성 약 5건.
  - 실제 5건 중 **한국어 자동 자막 2건 이상**, **40~60분 긴 영상 1건 이상**을 넣는다(자동 자막 인용 정확도·긴 입력은 실제 자료로만 볼 수 있다). 위 후보 6개는 영어 강의라 이 조건을 따로 채워야 한다.
  - **정답 카드의 기준은 원문(말·글)이다.** 코드와 원문이 다르면 모델 오류로 세지 않고 정답의 "모호한 점"에 넣는다. 코드에만 있는 조건을 모델이 쓰면 지어낸 조건이다(모델은 코드를 보지 않는다). 앞의 "영상 기준, 코드는 대조용"과 같은 뜻이다.
  - 모호한 점 재현은 주로 합성 자료로 본다. 합성 자료는 건마다 모호한 표현 2개 이상.
  - PDF 0건이어도 된다. PDF 경로는 knowledge-library-113이 나올 때까지 "(임시)"로 두고, 그때 PDF 3건 이상으로 따로 평가한다.
- **합성 자료는 템플릿 스크립트로 만든다(LLM 없음).** 규칙 빌더 JSON 조건마다 같은 뜻의 문장 템플릿 여러 개, 모호한 표현·규칙 불가 문장·잡담은 고정 목록, `[mm:ss]`는 스크립트가 매긴다. 정답이 생성 과정에서 나온다. LLM 다듬기는 숫자·뜻이 바뀔 위험이 있어 지금은 쓰지 않는다(필요해지면 `openai/gpt-6-luna` openrouter `--data public` 바꾸어 쓰기 + 숫자·단어 대조).
- **채점은 SIW 스크립트가 한다.** eval 파일에 `responseSchema`(strict 카드 스키마)·`maxTokens` ≥ 6000, `checks`는 json·기본 json_path만. 게이트웨이가 `models eval`로 세 모델을 돌려 리포트(`results[].answer`)를 주면 SIW 스크립트가 정답 카드와 조건 단위로 비교한다. 인용 대조는 제품의 인용 대조 스크립트를 그대로 쓴다.
- **합격 기준(게이트웨이 제안, 이대로 쓴다):** 지어낸 조건 0건, 인용 일치 ≥ 95%, 진입·청산·손절 필드 일치 ≥ 90%, 모호한 점 재현율 ≥ 70%.
- **순서:** ① SIW가 평가 세트를 만든다(실제 자료 파일은 로컬, data private, 합성만 있는 세트는 public 가능) → ② 경로를 보내면 게이트웨이가 eval 실행·리포트 경로·비용 회신 → ③ SIW 채점 결과를 보내면 배정 확정.
- **한국어·긴 영상 후보(미정):** 한국어 영상에 공개 코드가 짝지어진 곳은 2026-11-13 검색으로 찾지 못했다. 대신 규칙이 정해진 고전 기법(래리 윌리엄스 변동성 돌파, 터틀 트레이딩)을 설명하는 한국어 영상을 쓰고, 위 영어 저장소의 같은 기법 코드를 대조용으로 쓰는 안을 둔다(정답 기준은 여전히 한국어 원문). 영상은 사용자가 고른다.
- **먼저 확인할 것:** strict json_schema는 공급자마다 스키마 크기·깊이 제한이 있다. 카드 스키마로 1건을 먼저 보내 HTTP 400이 나는지 본다.
- **구현(2026-11-13):** `services/technique_cards/`(스키마·인용 대조·합성 생성·채점·프롬프트 v1)와 `python -m services.technique_cards.evalset synthetic|real|score`. 정답의 각 조건은 `terms`(모두 맞아야 하는 대안 묶음, `#`는 정확한 숫자)와 `exclude`(반대 방향 단어)로 맞춘다 — 모델 문장이 조건을 말하는지 스크립트로 판정하기 위해서다. 실제 자료 정답 카드도 같은 형식(`conditions`·`ambiguities`·`inexpressible`·`other`, 항목마다 `locator`·`quote`)으로 쓴다.

#### 합성 평가 결과 `[회신 #SIW-lib-5]` (2026-11-13, 합성 5건, 프롬프트 v1)

- **스키마:** 조건 객체를 7칸에 펼친 원래 스키마는 Anthropic 공급자(sonnet·haiku)가 "compiled grammar is too large"로 HTTP 400을 냈다. 조건 객체를 `$defs`에 한 번만 두고 `$ref`로 가리키자 세 모델 모두 받았다(출력 모양은 같음). `card_schema.py`를 그렇게 바꿨고, 스키마를 바꿀 때마다 haiku 1건으로 다시 확인한다. local-ai-gateway `3827d43`부터 OpenRouter 오류에 공급자 원래 사유(`error.metadata.raw`)가 붙는다 — SIW가 직접 부를 때도 그 값을 읽는다.
- **채점(SIW `score`):**

  | 모델                | 지어낸 조건 | 인용 일치 | 진입·청산·손절 일치 | 모호한 점 재현 | 잘못 둔 조건 | 5건 비용 |
  | ------------------- | ----------- | --------- | ------------------- | -------------- | ------------ | -------- |
  | `claude-sonnet-5.5` | 0           | 100%      | 100%                | 72.7%          | 2            | $0.1227  |
  | `openai/gpt-6-luna` | 0           | 100%      | 100%                | 100%           | 9            | $0.0056  |
  | `claude-haiku-5.5`  | 0           | 100%      | 100%                | 90.9%          | 6            | $0.0094  |
  - 세 모델 모두 합격 기준(지어낸 0, 인용 95%, 필드 90%, 모호 70%)을 넘었다. 합성만으로는 확정하지 않는다(합의).
  - **문제 — 잘못 둔 조건:** 세 모델 모두 기준 없는 말("양봉이 힘 있게", "거래량이 충분히 터져야", luna는 "시장 분위기가 좋을 때"·"애매하면 빨리 정리"까지)을 진입·청산 조건으로 넣었다. 출처 표시가 붙어 있어 그대로 전략에 들어갈 위험이 있다. 합격 기준에는 없던 항목이다.
  - sonnet이 놓친 모호한 점 3건은 모두 "애매하면 빨리 정리"를 표현 불가로 둔 것이다. 이 분류도 그럴듯해 채점 기준(모호한 점만 인정)을 바꿀지는 게이트웨이와 정한다.

- **대응:** 프롬프트 v2 — 진입·청산·손절에는 백테스트가 그대로 시험할 수 있는 조건만, 기준 없는 말은 숫자로 정할 수 있으면 모호한 점, 아니면 표현 불가로(둘 다 넣지 않음). 합성 v2 세트(`data/technique_eval/synthetic-v2/`)로 다시 돌리고, "잘못 둔 조건 0"을 합격 기준에 더할지 게이트웨이에 묻는다(`[요청 #SIW-lib-6]`).

- **다시 볼 조건:** 인용 대조 실패가 조건의 5% 초과, 지어낸 조건 1건 이상, 건당 $0.3 또는 월 $40 초과. 아래 재검토 조건의 "20%"는 이 5%로 바꾼다.
- **게이트웨이 제안(결정은 SIW·사용자):** 순서를 카드 → 규칙 빌더 JSON(LLM, strict) → Pine(스크립트 템플릿)으로 바꾼다. 빌더가 표현하는 조건은 템플릿으로 Pine을 만들고, 표현 못 하는 조건만 LLM이 Pine을 쓴다. Pine → JSON 변환에서 의미가 어긋나는 위험을 줄인다. ADR 0042의 Pine 먼저 순서와 달라 사용자에게 물었고, 2026-11-13 사용자가 규칙 빌더 먼저로 정했다(§4).

## Alternatives

- **cpl 세션 전달 묶음으로 SIW `docs/inbox`에 받기:** 지금 바로 가능하지만 주간 묶음이고 앱 화면과 맞지 않는다. 사용자가 도서관 경유를 골랐다.
- **SIW가 직접 자막·PDF를 받기:** 도서관·Commonplace와 기능이 겹치고, 출처·권리·철회 관리를 다시 만들어야 한다.
- **카드만 만들고 전략은 사용자가:** 사용자가 규칙 빌더까지를 골랐다. 단 각 단계 저장은 사용자가 누른다.

## 재검토 조건

- 도서관이 매매기법 자료를 SIW에 열지 않기로 하면 §2를 다시 정한다.
- 인용 대조 불일치가 카드 조건의 5%를 넘거나 지어낸 조건이 나오면 모델·프롬프트를 다시 배정받는다.
