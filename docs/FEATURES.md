## 2. 시장 데이터

### 2.1 공급업체와 출처

- **기본값은 합성 데이터**다. `SIW_MARKET_DATA_PROVIDER=alpaca`일 때만 외부를 호출한다. Alpaca(SIP, 데이마켓은 BOATS)를 미국 기본 공급업체로 정했다(ADR 0035). Massive는 미검증 대체 후보다.
- **합성:** `FakeMarketDataProvider`, 합성 `SYNTH` 하루치. 새 프로필은 공급업체가 SYNTH를 주지 않으면 첫 제공 종목(Alpaca는 SPY)으로 연다.
- **Alpaca** [실확인]: 1분봉(Decimal, 페이지네이션), 일봉, 수정 일봉(`split`/`all`), BOATS 데이마켓, 체결(`trade_pages`), 자산 목록, 기업 행위, 뉴스(읽기 전용, 이후 news-analysis로 이전), SIP `statuses` 스트림. 체결 없는 분은 `provider_no_bar`, 권한 밖 구간은 `outside_entitlement`, 미확정은 `not_yet_final`로 표시한다.
- **증권사 시세 adapter** — 허용 경로만 호출하고 주문 경로는 `BlockedEndpointError`로 막는다(ADR 0013).
  - 토스 [실확인]: 미국 1분봉·일봉, 국내 봉(KRX+NXT, `toss-kr`), 국내 수정 일봉, 시세·호가, 실시간.
  - 키움 [실확인]: 미국 1분봉(뉴욕 시각 봉 시작으로 확정).
  - 메리츠 [미확인]: 분봉(최근 40개, 넘으면 `beyond_source_history`), 일봉, 현재가, 실시간. 실계좌 키 도착 전.
  - 한국투자(KIS) [미확인]: 분봉 adapter만 있고 실계정 확인이 없다.
  - 미래에셋: 공식 시세 API가 없어 지원하지 않는다.
- **출처를 섞지 않는다:** 공급업체·feed·리비전·수정 방식·모의/실전이 다른 봉은 같은 캐시·집계에 넣지 않는다.
- **환율:** 한국은행 ECOS(731Y001) [실확인], 토스 참고 환율.

### 2.2 저장과 캐시

- `SIW_DATA_DIR`가 있을 때만 캐시를 쓴다. SQLite(번호 migration, 리비전, Coverage, 작업·checkpoint, 리비전 pin, write journal)와 내용 해시 파일명의 immutable Parquet(`session_date=` 파티션).
- 원자적 쓰기·중단 후 복구·다중 프로세스 잠금(owner lock). 미확정 봉이 있는 캐시는 재사용하지 않는다.
- 결측 없는 캐시 여러 개를 조합해 다른 요청 범위에 응답한다. `available_at_utc`만 다른 같은 봉은 가장 이른 시각으로 합치고, 값이 다르면 그 범위를 다시 받는다(ADR 0002 보강).
- 일봉은 종목·연도 단위 캐시(올해는 매번 새로 받음, ADR 0015). 수정 일봉은 캐시하지 않는다.
- Collector `backfill`: 범위 하나가 작업 하나, chunk별 checkpoint, 재개·재시도·throttle [실확인: Alpaca 하루 960분].
- 남은 것: 자동 retention/GC 없음, 네트워크 공유 SQLite 미지원.

### 2.3 시간·세션·집계

- 거래소 캘린더(`exchange-calendars`) — 미국 XNAS/XNYS(`America/New_York`, DST·휴장·반장), 국내 XKRX/XKOS(정규 09:00–15:30, NXT 08:00–09:00·15:30–20:00). 범위 2000-01-03~2030-12-31, `calendar_version`은 일정 SHA-256.
- 미국 연장 세션 정책: 장전 04:00–09:30, 정규, 장후 20:00(반장 17:00) ET.
- 데이마켓(BOATS): 거래일 D의 데이마켓은 전날 20:00~D 04:00 ET. 정책 `us-overnight-boats-v1-2026-10-22`, Blue Ocean 공지·토스 달력과 대조했다. 뉴욕 20:00 이후 오늘 차트는 다음 날짜의 진행 중 데이마켓도 받는다(ADR 0030). [실확인]
- 집계: 1분봉에서 2~960분 임의 분(`Nm`)을 세션 시작 기준으로 만든다. 세션을 섞지 않는다. 일봉은 정규장 기준이고, 주봉은 일봉에서 집계한다. 품질 `complete`/`partial`/`provisional`과 lineage를 남긴다.
- 시점 기준 조회: `as_of_utc` 이후 공개된 봉은 돌려주지 않는다. 확정 봉은 구간 종료 전에 공개될 수 없다.
- 차트 일·주봉은 분할 수정 가격(`adjustment=split_adjusted`)을 요청하고, 분봉과 리플레이는 비수정이다.

### 2.4 종목·티커

- 종목 검색(`GET /v1/market/symbols`): Alpaca 자산 목록(하루 1회, 백그라운드 갱신, 저장 사본으로 즉시 응답) + 토스 국내 약 4,300종목(한글명). 미국·국내 통합 순위 [실확인].
- 종목 ID: 미국 `us:<symbol>:<MIC>:2026`, 국내 `kr:<6자리>:<xkrx|xkos>:2026`. 우선주 하이픈 표기(`ROOT-X`)는 후보 중 하나로 해석한다.
- 티커 변경·상장폐지 추적(ADR 0033): Alpaca 기업 행위로 체결일 티커를 현재 티커에 연결하거나 상장폐지 ID로 등록한다. 재사용된 티커는 별도 ID(`reused_on`), 로컬 보충 `symbols/renames-local.json`. 검색에서 "상장폐지 · 마지막 거래일", "구 티커"로 표시한다. 상장폐지 종목 거래소는 SIP 테이프·종가 단일가로 판정했다. [실확인: 실데이터 재키잉]
- `scripts/check_ticker_reuse.py`: 해석 기록 없는 체결을 SIP 1시간봉과 비교한다(읽기 전용).

### 2.5 시세 부가 정보(토스·기타)

- 실시간 시세 패널: 현재가·호가·최근 체결 30건·가격 제한. 출처는 토스/메리츠 중 고른다.
- 실시간 중계 `WS /v1/realtime`: API가 토스 WebSocket 하나를 열어 체결·호가·내 주문을 중계한다(Origin 검사, 재연결). 국내 종목도 구독한다. 틱은 `data/ticks/` Parquet에 저장하되 봉·백테스트에는 쓰지 않는다(`GET /v1/market/ticks`). [실확인]
- 종목 정보(`stock-info`), 토스 장 운영 시간(`broker-calendar`), 환율.
- 리서치 패널(`GET /v1/research/{dataset}`): 토스 리서치 14종(랭킹, 지수·금리, 투자자별 매매, 섹터, 국내 수급·공매도·신용·대차). [실확인]
- 랭킹 패널(`GET /v1/rankings`, ADR 0049): 거래대금·거래량·급등락·토스 거래 상위·국내 투자자별 순매매. 종목을 누르면 차트에 연다. [미확인: 실계좌 토스 응답]
- 공시 판독 분할·병합(ADR 0046): 주식 희석 분석기의 `splits.sqlite`를 읽기 전용으로 읽어 차트 아래 "공시 판독값, 미대조"와 봉 위 `분할 10:1` 표식으로 보인다. Alpaca 분할과 다르면 다른 색. 가격·백테스트에는 쓰지 않는다. SEC 원문은 `STOCK_SHARED_DATA`로 분석기와 공유한다.

### 2.6 API 키 관리

- "API 키 관리" 화면: 공급업체별·계좌별 여러 키 등록, 순서·사용 여부·secret 교체·삭제. secret은 **OS 키체인**에만 두고 다시 보여주지 않는다. 계좌는 별칭과 끝 4자리만 저장한다. `.env`의 키는 읽지 않는다(ADR 0014). [실확인: macOS 키체인]
- 계좌 구분 실전/모의(모의는 키움 `mockapi`, KIS 모의 도메인). 모의 데이터는 실전과 섞지 않는다.
- 한도 오류를 받은 키는 60초 건너뛰고 다음 키를 쓴다. 다른 오류는 넘기지 않는다. [미확인: 실제 한도 전환]
- 등록 항목: Alpaca, 토스, 키움, 메리츠(MAC 주소 포함), KIS, Anthropic, FINRA, ECOS, OpenRouter.
- 키움 MCP(`kiwoom-exec`)는 `scripts/kiwoom_mcp_launcher.py`로 첫 키움 키를 읽어 시작한다.

## 3. 차트 화면(SIW Research)

### 3.1 화면 구성

- 전체 화면 터미널 레이아웃: 상단 도구줄(검색·봉 단위·보조지표·레이아웃·리플레이·되돌리기·워크스페이스), **왼쪽 사이드바**(일 묶음별, 접기·펼치기), 차트 위 **종목 띠**(종목·거래소·봉 단위·날짜와 시가·고가·저가·거래량, 리플레이 중에는 숫자를 숨김), 그리기 도구, 옆 패널 또는 차트 옆 작업 화면, 하단 거래일 이동·시계, 상태 줄(연결·도움말·버전·API 주소·언어).
- 왼쪽 사이드바(디자인-siw-1 r4). 같은 자리 탭은 "/"로 적는다.
  - **종목:** 관심종목(⌘1, 떠 있는 창으로 분리 가능), 종목(실시간 시세 / 종목 정보).
  - **발굴:** 종목 발굴(⌘2) — 오늘의 후보 / 조건검색 / 리서치 / 랭킹.
  - **매매:** 계좌·원장(⌘3) — 계좌 조회·동기화, 매매일지(원장 4종), 대사, CSV 가져오기를 한 패널에 접어 둔다. 차트 AI 해설(옛 "복기 Agent").
  - **작업 화면**(차트 옆에 넓게 열림): 매매 복기(⌘4), 전략 연구(백테스트 / 기법 카드).
  - 맨 아래 **설정**(⌘,): 대화상자 하나에 "연결·키"(API 키 관리)와 "AI 모델·리포트"(매매 복기 리포트 설정, 기법 카드 기본 모델). 언어는 상태 줄, 저장소 폴더는 앱 메뉴에서 바꾼다.
- 대화상자는 같은 틀을 쓴다(설정·보조지표·지표 설정·도움말 등): 열면 첫 입력칸이나 첫 버튼에 초점, Tab이 밖으로 나가지 않음, Esc·바깥 클릭으로 닫힘, 닫으면 연 버튼으로 초점이 돌아감. [테스트]
- 디자인 시스템 "Deck"(어두운 테마 하나): `styles.css` 맨 위 `--siw-*` 토큰과, 차트처럼 CSS 변수를 못 읽는 곳에 넘기는 `theme.ts`. 원장 다섯 종류에 서로 다른 색(수동·가져오기·증권사·가상·백테스트).
- Electron 앱 메뉴: "설정…"(⌘,), 도움말 "구현 기능 안내"(F1). 화면 안 상태 줄의 "도움말" 버튼도 같은 안내를 연다.
- 레이아웃 1·2·4(2×2) 차트, 차트마다 종목·봉 단위·날짜·세션·지표를 따로 둔다. 시간 범위 동기화.
- 이름 붙인 워크스페이스(저장·전환·이름 변경·삭제), Trading Terminal·Trade Review 템플릿, 20단계 되돌리기(ADR 0010).
- 언어: 한국어·영어(`siw.language`).
- 종목 시장에 맞춰 시간대(ET/KST)·캘린더·가격 자릿수를 바꾼다.

### 3.2 차트 조작

- 종목 검색 팝업(차트에서 글자 입력 또는 Ctrl/⌘+K), 관심종목(이 기기에 기억).
- 봉 단위 즐겨찾기(기본 1m·5m·15m·30m·1h), 프리셋, 직접 입력(최대 16시간), 1D·1W.
- 기본 약 1,200봉. 분봉은 최대 60거래일. 앱을 열면 그 거래소의 오늘(휴장이면 최근 거래일).
- 정규장 / "장전·장후·데이마켓" 보기(데이마켓은 별도 색 시리즈).
- 이전 봉 불러오기: "◀ 이전 봉" 버튼 또는 활성 차트에서 **스페이스 키**(스크롤 자동 로딩은 없앴다). 한도 12,000봉, 거래정지 공백은 일봉으로 건너뛴다.
- 자석·로그·전체 보기, 십자선 범례(OHLC·변화·거래량·미확정).
- 일봉 **프리마켓** 켜기(ADR 0041): 장전 OHLC를 일봉 뒤 반투명 주황 캔들로 깔고 일봉 몸통을 반투명으로 바꾼다. 최신 봉에 "PM 고가" 가격선. 분할 수정 일봉이면 세션 비율로 환산한다. 최근 60세션. [실확인: AAPL·NVDA]
- 분할·병합 표식(Alpaca + 공시 판독값).
- 체결 마커: 수동(실제)·가상·가져오기("I")·증권사 API("B", 주황)·백테스트("BT", 분홍). 같은 봉·같은 방향은 `B buy ×12 (340)`처럼 묶는다. 캔들을 클릭하면 그 캔들의 기록 목록.
- 후보 검사 결과의 가격선을 차트에 그리기(기본 꺼짐).

### 3.3 보조지표

- **내장 34종**(직접 구현): SMA·EMA·WMA·VWMA·HMA·엔벨로프·SAR·슈퍼트렌드·일목·아룬·DMI/ADX, RSI·MACD·스토캐스틱·StochRSI·CCI·%R·모멘텀·ROC·AO·TRIX·UO, 볼린저·켈트너·돈치안·ATR·BB폭·%B·HV, VWAP·OBV·MFI·CMF·거래량 MA. Python 백테스트 엔진과 1e-9 파리티.
- 워밍업: 가장 긴 기간의 3배까지 이전 봉을 계산에만 쓴다.
- 설정 창(TradingView식, ADR 0039): 입력(기간·시간대·소스), 스타일(표시·색·굵기·선 모양·투명도·소수점·기준선), 가시성(시간대별 on/off).
- 다른 시간대 지표: 분봉 차트에서 더 큰 분봉(15~240분)·1D·1W, 더 작은 분봉(1~10분). 확정·공개된 봉만 쓴다(ADR 0027, 0034, 0039).
- **수식 지표**(ADR 0026): 가격 필드·사칙연산·허용 함수 20개, 직접 만든 파서(`eval` 없음).
- **Python 사용자 지표**(ADR 0023): `update(ctx)` 규약, 별도 프로세스 샌드박스(30초·5,000봉), 버전(SHA-256), 미리 계산, "↑vN" 버전 올리기. 샌드박스는 사고 방지용이며 악의적 코드에 대한 보안 경계가 아니다.
- **Pine Script**(ADR 0040): v5/v6 대부분을 앱 안에서 해석한다(eval 없음). 타입·switch·method·배열·문자열, ta 함수 확장, plotshape·bgcolor·fill·line·label·box·table, `request.security`(확정 값만), `strategy()`는 차트 위 백테스트로만(주문·원장 기록 없음). 미지원: 사용자 정의 타입·matrix·map·polyline·plotcandle. TradingView와 결과 대조는 하지 않았다.

### 3.4 그리기·리플레이

- 그리기(저장): 추세선, 수평선, 피보나치 되돌림, 추세 기반 피보나치 확장(TradingView식 레벨·색 띠·설정 패널), 텍스트 메모. 임시: 측정·확대. 캔들 시각·가격에 고정, 종목별로 저장.
- 리플레이: 캔들 클릭으로 시작, 한 단계 앞·뒤, 재생 1x~10x, 모든 차트에 적용. 서버 `as_of_utc`로 그 시점에 공개됐던 봉만 다시 받는다(공급업체 지연 반영). 리플레이 중에는 실시간·이전 봉·관심종목 가격을 멈춘다.

## 4. 매매 기록·원장

### 4.1 원장 종류(서로 합산하지 않음)

| 원장                | 입력                                        | 손익                                  |
| ------------------- | ------------------------------------------- | ------------------------------------- |
| 수동 기록(실제)     | 캔들 클릭 + 시각·가격 입력(거래소 현지시각) | FIFO                                  |
| 가상 시나리오       | 캔들 클릭                                   | 시나리오별                            |
| 거래내역서 가져오기 | CSV                                         | FIFO                                  |
| 증권사 API 체결     | 토스·키움·메리츠 동기화                     | 계좌·종목별 FIFO(`account_positions`) |
| 백테스트 체결       | 백테스트 실행 결과(원장에 쓰지 않음)        | 백테스트 결과 안에서만                |

- `journal.sqlite3`, 추가 전용·멱등(다른 내용이면 409). USD·KRW 모두 받고 종목 시장과 통화를 검증한다.

### 4.2 CSV 가져오기(ADR 0011)

- 열 매핑 추천·편집, 행별 미리보기(새 행/이미 가져옴/중복 가능/오류), 중복 가능 행은 사용자 결정, 같은 파일(SHA-256)은 한 번만. 원본 파일과 매핑하지 않은 열(계좌번호)은 저장하지 않는다. KST 입력 지원. [실확인: 브라우저]
- 미구현: 증권사별 preset, XLSX, batch 무효화.

### 4.3 증권사 체결 동기화(읽기 전용)

- **토스**(ADR 0018): 체결이 있는 종료 주문 1건을 1행(`order_aggregate`)으로 저장. 재동기화해도 중복 없음, 값이 바뀐 주문은 `conflicts`로 알림. 국내·미국 모두. [실확인]
- **키움 미국**(ADR 0029): ust21150 일별 주문체결, 기본 1년·최대 5년. 서울 시계 → 미국 거래일·데이마켓 배치. 정산 수수료 ust21100을 `broker_fee_lines`로 받아 포지션 손익에 반영. [실확인: 실계좌, 건수만]
- **키움 국내**: kt00015 정산 라인(체결 시각 없음, 날짜만). [실확인]
- **메리츠**(ADR 0043): 해외 주문체결, 계좌 스냅샷. [미확인: 체결 시각 시간대 등]
- 계좌 패널(조회 전용): 토스 계좌·보유·매수 가능 금액·미체결·조건주문, 메리츠 계좌, 동기화 버튼들.
- 실계좌 실행기가 무장된 동안 같은 키움 키의 조회 동기화는 409로 거절한다.

### 4.4 대사(ADR 0025)

- `GET /v1/trades/reconciliation`: 증권사 API 체결과 수동·거래내역서 기록을 수량·가격 허용 오차(기본 10bp)·시각 창으로 비교해 일치/불일치/한쪽에만으로 분류한다. 원장은 바꾸지 않고 저장하지 않는다. 종목별·일별·기록 목록, 필터, 드릴다운.
- [미확인] 실제 사용자 수동·거래내역서 기록과의 대사(현재 실데이터는 증권사 API 체결뿐).

## 5. 백테스트(ADR 0021, 0031, 0032)

- **전략:** 규칙 전략(조건·지표·손절/익절·수량, 버전 불변 SHA-256)과 Python 전략(`on_bar(ctx)`, 샌드박스).
- **엔진:** 다종목·단일 통화·매수 전용. 확정 봉 종가 신호 → 다음 봉 시가 체결, 수수료·슬리피지(Decimal). 같은 봉 손절·익절은 손절 우선. 단순 보유 벤치마크. 입력 고정(출처·리비전·봉 해시·누락), 분할 의심 경고.
- **규칙 빌더:** 34개 지표·Python 지표(`py:<id>@<버전>`)·이전 N봉 값·시간대 조건·ATR 손절·트레일링 스톱·주문 유형(시장가/지정가/스톱, 오프셋 %, 유효 봉 수).
- **기간:** 시작~종료일 또는 시작일부터 N봉(최대 5,000, 최대 3,000세션).
- **수정주가:** 미국 일·주봉 raw / split_adjusted / fully_adjusted(Alpaca), 국내 split_adjusted(토스, 유·무상증자 포함). 화면 기본은 분할 수정. [실확인: NVDA, 삼성전자]
- **워크포워드:** 표본 내·외 구간, 최대 3개 파라미터 격자, 고정 시작(`anchored`), 규칙·Python 전략 모두.
- **화면:** 백테스트 창(폼·코드·JSON 편집, 저장 후 실행, 폴링·취소), 결과(경고·지표 카드·자산·낙폭 곡선·종목별·거래·미체결·고정 입력), 차트 `BT` 마커, 실제 체결과의 비교.
- `backtests.sqlite3` 대기열(백그라운드, 취소 가능). 백테스트 체결은 원장에 쓰지 않는다.
- 한계: 공매도 없음, 생존 편향(상장폐지 종목 미포함), 분봉은 정규장만, 수식 지표는 규칙에 못 씀.

## 6. AI 기능(Claude 등)

모든 LLM 호출은 사용자가 누를 때만 나간다. 보낼 내용을 미리 보여주고, 계좌 참조·기록 ID·키는 보내지 않는다. 매매 권고는 금지한다. 근거(사실)와 해설(추론)을 분리해 저장한다.

### 6.1 차트 AI 해설(옛 이름 복기 Agent, ADR 0022, 0024)

- 결정적 근거 생성: 차트 시점(`as_of`), 실제 체결(계좌별 FIFO, MFE/MAE, 정산 수수료, 통화 혼합 거부), 백테스트 비평(표본 수·비용 비중). `agents.sqlite3`.
- 공시 Agent: SEC EDGAR(`SIW_SEC_USER_AGENT` 필수, 초당 5회), 기준 시각 이전 공시·8-K·XBRL. [실확인: AAPL 1,001건]
- 다크풀 Agent: FINRA 주간 ATS. [미확인: FINRA 토큰 `400 invalid_client`로 실패]
- 화면: 사이드바 "매매 → 차트 AI 해설" 패널, 캔들 팝업 "Agent에게 묻기", 백테스트 "Agent 비평". 보낼 내용은 "보낼 내용 보기"를 펼쳐 볼 수 있다(펼치지 않아도 보낼 수 있다).

### 6.2 매매 복기(ADR 0042)

- **1단계 거래 묶음:** 원장·계좌·종목·전략별 FIFO, 묶음 규칙 `flat`/`day`/`fifo`/`manual`, 전략 지정·수동 묶기·메모·태그·복기 완료. 거래 차트(5분·일봉, 청산 이후는 사후 표시). [실확인: 체결 108,925건 사본]
- **2a 거래 리포트:** 거래 사실 + 갭·프리마켓 고가·SPY·QQQ 상대 강도 + 차트 이미지(기준 시각 이후 봉 제외)를 Claude에 보내 구조화 리포트(진입·청산·비중). 계좌별 운용금 설정. [실확인: Sonnet 5.5]
- **2b 후속 질문:** 리포트별 대화, 읽기 전용 도구(`get_bars`·`get_indicator`·`chart_image`·`strategy_signals` 등, 기본 청산 시점까지). [실확인]
- **3a 매매 원칙:** 버전 저장, 숫자 항목 6종 + 글 항목, 글→항목 변환은 Claude가 제안만 하고 사용자가 저장. 거래가 열린 시각의 버전으로 판정(지킴·어김·해당 없음·판단 불가).
- **3b:** 사후 가정("원칙대로", "전략대로"), 전략 추천, 목록 원칙 열·필터, 백그라운드 점검(최근 90일 자동, 대기열 저장).
- **4a 기간 리뷰:** 통화별 성적·위험·원칙별 손익·묶음표·누적 곡선·일별 달력, 직전 기간 비교, 만든 시점 그대로 저장(최대 400일). Claude 없음. [실확인]
- **4b 기간 해설:** 통계·원칙·상하위 거래를 보내 해설과 원칙 변경 제안을 받는다. 고른 제안만 원칙 편집기에 연다. 후속 질문(`period_trades` 도구). [실확인]

### 6.3 보조지표 만들기(Claude와 Pine)

- 차트 옆 떠 있는 창. Claude가 `run_pine` 도구로 스크립트를 실행해 요약만 받으며 고친다(요청당 6회, 실패 시 Sonnet high → Opus 재시도). 점선 미리보기, "차트에 추가"/"지표에 적용", 이어서 고치기.
- 출발점: 새 지표 / 내 Pine 지표 / TradingView 코드 / 내장 지표 변형. 차트 이미지 첨부(PNG ≤3 MB, 대화당 5개).
- 기본 모델 Sonnet 5.5 medium(배정 #SIW-1). [실확인: 합성 SYNTH, 실제 Claude]

### 6.4 전략 연구·규칙 전략 변환

- 전략 연구 대화(`StrategyResearch.tsx`): Pine 편집기·Pine 전략 설정에서 연다. 결과 보내기(요약·최근 50건·일자별 집중도), 진단 스크립트(`purpose: diagnostic`). Sonnet 5.5 high, 재시도 Opus 5.5 high(#SIW-2). [실확인: 파일럿 A]
- 규칙 전략 변환: Opus 5.5 high 구조화 출력 → 조건별 규칙 위치 → 같은 봉으로 Pine·규칙 엔진 비교(`comparison`) → 기준(거래 20건 이상, 거래 수 10%, 순손익 20%, 진입 일치 80%)을 모두 통과할 때만 새 규칙 전략 버전으로 저장. 막히면 409 `conversion_not_savable`. [실확인: 파일럿 B, 실제 Claude 3건]

## 7. 종목 선정·스크리닝(ADR 0048, 0051, 0052, 0053, 0055, 0057)

### 7.1 확정된 7단계 흐름(ADR 0057)

| 단계 | 내용                                 | 구현 상태                                          |
| ---- | ------------------------------------ | -------------------------------------------------- |
| 1    | 모멘텀 수집(키움 조건검색 편입)      | 구현 — 조건검색 패널, 실시간 기록기, 모멘텀 열     |
| 2    | 재료 영향력(저영향이면 그날 제외)    | SIW 몫 구현 — news-analysis 서비스 결과로 판정     |
| 3    | 실시간 수급(지금 시점만 제외)        | 구현 — `GET /v1/screening/flow`, halt 기록기       |
| 4    | 희석·장외 체결·공매도 정보(LLM 없음) | 구현 — 30초 자동 실행(공매도는 자료 없음으로 생략) |
| 5    | 차트 모니터링·가격대                 | 미구현(규칙 별도 논의)                             |
| 6    | 전략 틀에 진입·청산 가격대           | 미구현(별도 논의)                                  |

사용자는 흐름만 정하고 종목을 고르지 않는다. 움직임 분류·피보나치·진입조건 A는 폐기했다.

### 7.2 구성 요소

- **키움 조건검색 패널:** 연결한 미국 조건식 3개(`SIW_전일신고거래량`, `SIW_당일급등주`, `SIW_전일급등주`)만 이름으로 찾아 실행한다. 보낼 수 있는 WebSocket 메시지를 제한한다. 결과는 저장하지 않는다. [실확인: 실계좌 키]
- **실시간 조건 기록기** `watch-condition`: 뉴욕 04:00–20:00에 `SIW_당일급등주` 편입·이탈을 `kiwoom_condition_watch.sqlite3`에 덧붙인다. 30분마다 구독 갱신, 끊기면 재연결. `export-condition`. [실확인: 일부 시간대 침묵 원인 미확인]
- **halt 기록기** `watch-halts`: 뉴욕 03:58–20:00 Alpaca SIP `statuses` 전 종목을 `sip_status_watch.sqlite3`에 기록한다. [실확인: 연결·하트비트만, 장중 실제 halt 미확인]
- **오늘의 후보 패널**(`CandidatesPanel.tsx`): 조건검색 기록에서 후보 목록, 편입 횟수·머문 시간·편입 시점(Alpaca), 기록 빈틈 줄, 정오 전환(`as_of`). 열: 재료(2단계), 지금 수급(3단계), 정보(4단계), 뉴스 B, 희석 C, 장외 체결 D, 가격 구조.
- **B 뉴스 재료:** news-analysis 서비스(`127.0.0.1:8776`) 클라이언트. 45초 대기 후 `pending`, 다시 보기. NIR 요약(추론 표시). 두 결론("걸러야 할 재료인가", "급등의 명분인가")으로 통과·그날 제외·재료 미확인을 정하고, cutoff 시가총액(앞선 세션 희석 분석기 주식 수, 없으면 토스 발행주식수 + 경고 × cutoff 전 종가)을 함께 보낸다. 후보마다 세션당 한 번 자동 실행(`NewsAutoRunner`, `SIW_SCREENING_NEWS_AUTO=0`이면 끔). [미확인: 실제 서비스와 이어 본 확인, 장중 자동 실행]
- **C 희석 공급 가격대:** 주식 희석 분석기 서비스 호출(규칙만, 고른 종목에만 LLM). [미확인: 성공 경로]
- **D 장외 체결(TRF 보고):** Alpaca SIP 체결 중 FINRA ADF(`D`)의 가격대별 거래량·봉우리·장외 비중. 닫힌 20세션은 세션 캐시에서, 오늘만 직접 읽는다. 장 마감 뒤 미리 받기(`SIW_SCREENING_PREFETCH=0`이면 끔). 명령 `python -m services.screening.off_exchange`. [실확인: STAK·AAPL]
- **장외 체결 가격 구조 모델**(ADR 0053): 세션 가격대 캐시, Decimal 모델, 불변 등록부, 사후 판정·walk-forward·shadow audit. [미확인: 실제 20세션·평가 데이터셋]
- **3단계 수급:** 분마다 유동성 4/5·변동성 3/20, halt 중 빈 분은 제외. 주문 기능 없음. [실확인: 오늘 후보 12개]
- **4단계 자동 실행:** `Stage4Runner`가 30초마다 세션 창 안에서 2단계 통과 후보에 C(규칙만)·D(주기당 2종목)를 돌린다(`SIW_SCREENING_STAGE4=0`이면 끔). [미확인: 장중 실제 실행]

## 8. 기법 카드(ADR 0056)

매매 기법 영상·자료를 근거 인용이 붙은 카드로 만들고, 규칙 전략 초안까지 잇는다.

- **L1 자료:** 지식 도서관(knowledge-library) CLI만 쓴다. 태그 `매매기법` 구독 전달 → current 자료만, 자막은 저장소 밖 캐시(0700/0600). 다시 쓰기 전마다 `hydration-check`, 철회되면 캐시를 지우고 카드에 근거 철회를 표시한다. [실확인: 18건 조회]
- **L2 카드 추출:** 구간별 구조화 출력(조건 칸, 숫자별 인용). 스크립트 검사(근거 없음·기준 없음·모델 추론·원문 타임라인). 표시된 조건은 사용자가 확인·수정·삭제해야 "준비됨". 건마다 모델·토큰·비용 기록, 원문은 저장하지 않고 해시만. 미리보기에서 보낼 내용과 추정 비용을 먼저 보인다.
- **모델:** 기본 모델 설정(`GET|PUT /v1/technique-settings`) — Argon(기본)·Astra. 실행마다 Argon·Astra·Sonnet 5.5·Luna 중 선택. OpenRouter(`data_collection: deny`). Fable 5.2는 임시 중지(요청하면 422, 저장된 기본값은 Argon으로 되돌림). 평가 세트로 검증한 모델은 Sonnet·Luna뿐이다.
- **L3 전략 초안:** 준비된 카드 → 규칙 빌더 전략. **스크립트 우선 변환**(`script_rules.py`, 모델 없이 조건 칸을 규칙으로) 후 남은 항목만 모델에 보낸다. "스크립트만(무료)" 선택 가능. 원문에 없는 해석은 목록으로 보이고 확인 체크가 있어야 저장. 사용자가 직접 추가한 조건(`resolutions.added`). 문제가 있거나 카드가 바뀌면 저장 거절.
- **평가 세트:** 합성 자막 생성기, 실제 자료 12+5건 정답 카드, 채점 규칙 v1~v3, 근거 대조(`grounding.py`). 명령 `python -m services.technique_cards.evalset synthetic|real|score`.
- **목록:** 카드마다 모델·만든 날짜(UTC)·판 표시.
- [미확인] Argon으로 섞어 만든 초안의 실제 실행, 모델이 뽑은 카드에서 스크립트 변환 비율.

## 9. SIW Agent 주문 실행

### 9.1 모의투자(단계 1, ADR 0037, 0044)

- `services/paper_trading/`: `PaperOnlyClient`는 **모의 도메인만** 호출한다(`scripts/check_paper_only.py`가 검사). `paper_orders.sqlite3`.
- 실행 계획 승인 마법사(전략·계좌 → 종목 → 한도 → 확인), 무장/해제, **킬 스위치**(신규 주문 중지, 누구나 정지 가능, 시작은 Tauri 출처만), 1건 100만 원 한도, 원화 한도용 ECOS 환율(`fx_source`).
- 신호: 규칙 전략의 확정 봉(출처 혼합 거부), 봉 확정 대기(`bar_settle_seconds`)·신호 최대 나이.
- 키움 모의 adapter: 미국 지정가 매수·매도·취소·당일 주문 조회. 시장가 의도는 유리한 지정가로 보낸다(모의는 지정가만 허용). 호출 간격 1.1초, 429 재시도.
- G1 미체결 주문 취소(`unfilled_cancel_seconds`), G2 보호 상태 저장, G3 보호 청산(손절·익절·트레일링을 바로 체결될 지정가로), `GET /v1/paper/positions` "보유와 보호 상태" 표.
- CLI `python -m services.paper_trading status|halt|release`.
- [실확인] 키움 모의 서버: 정규장 지정가 접수·체결·취소, 무장 상태 손절 청산, 킬 스위치 후 손절 청산, 미체결 취소·재판단. 프리마켓 주문은 "모의투자 장종료"로 거절.
- [미확인] 익절·트레일링 청산, 정규장 밖 지정가 매도, 상주 실행기 프로세스 전체 경로, Linux에서 키움 모의 호출. KIS 모의는 미구현.

### 9.2 실계좌(단계 2, ADR 0047)

- `services/live_trading/`: 실전 도메인 전용 클라이언트(주문을 보낼 수 있는 실전 host는 `client.py` 한 곳. 조회 adapter는 별도), 키움 실계좌 adapter, `live_orders.sqlite3`, 승인 대기 실행기, 사용자 서비스 `com.pensivetraveler.siw.agent.live-runner`. SIW Agent "실계좌" 탭.
- 한도·킬 스위치를 통과한 주문은 대기 → **사용자가 주문마다 승인** → 다음 주기에 재검사 후 전송. 60초 안에 승인하지 않으면 만료. `max_order_amount_usd`와 하루 주문 수(2건) 필수.
- [테스트] 가짜 키움 서버로만 확인. **실계좌 도메인으로는 아무것도 보내지 않았다.** L3(사용자 직접 무장·첫 주문 승인)는 진행 전이다. 코딩 Agent는 실계좌 주문을 내거나 실계좌 엔드포인트를 시험하지 않는다.
