# 실계좌 주문 런북 — L3 첫 주문과 단계 3 열기 조건

- **관련:** [ADR 0047](../decisions/0047-live-orders-per-order-confirmation.md)(실계좌 주문마다 승인, L3 사전 점검표), [ADR 0060](../decisions/0060-live-unattended-execution-stage3.md)(단계 3 무인, proposed), [ADR 0029](../decisions/0029-kiwoom-order-history-sync.md)(조회 전용 동기화)
- **대시보드:** `stock-intelligence-61`(L3), `stock-intelligence-7`(메리츠 체결 시각), `stock-intelligence-315`(ADR 0060 재확정)
- **규칙:** 실행 승인·무장·주문 승인은 사용자만 한다. 코딩 Agent는 실계좌 주문을 내거나 실계좌 엔드포인트를 시험하지 않고, 키·계좌번호·주문번호 원문을 다루거나 적지 않는다. Agent는 전후의 원장·로그만 읽는다.

## 2. L3 당일 순서 (사용자 조작)

ADR 0047의 순서 규칙: **같은 날 모의 확인을 먼저** 하고 실계좌로 간다. 미국 정규장은 23:30 KST(서머타임 해제 기간), 실행기 주기는 10초다.

**전날까지(사용자 확인, Agent는 확인 못 함)**

- [ ] kiwoom2 계좌에 미국주식 주문 권한과 달러 예수금이 있다(ADR 0047 L3 점검표: 실행기 키는 kiwoom2, 수집기는 Kiwoom1).
- [ ] 첫 주문 종목을 정했다. 1주 × 지정가가 **$100 이하**여야 한다. 넘으면 1건 한도에 막혀 주문이 나가지 않는다.
- [ ] 그날 밤 23:30~(최소 첫 진입과 청산까지) 자리에 있을 수 있다. 보호 청산과 15:45 ET 청산도 승인해야 나간다.

**당일**

1. **모의 먼저(`stock-intelligence-60`, siw-paper 세션 담당):** SIW Agent 모의 탭 → 전략 `strategy-0a1868c8e441` v1·해외모의 키로 실행 승인 → 무장 → 모의 상주 실행기 설치. 23:30 KST 뒤 모의 원장에 의도·제출이 남는 것을 확인한다. 모의가 막히면 그날 실계좌는 하지 않는다.
2. SIW Agent에서 **실계좌** 탭(붉은 띠 "실계좌 — 실제 주문")이 보이는지 확인.
3. 실계좌 탭에서 **상주 실행기 설치** → 무장 전에는 heartbeat만 쓰는지 본다.
4. **실행 승인:** 전략 `strategy-0a1868c8e441` v1 · 종목(위에서 고른 것) · 실전 키 **kiwoom2** · `max_order_amount_usd` **100** · 하루 주문 **2**건.
5. **무장.** 진입 신호는 09:45 ET(23:45 KST) 이후 1분봉 SMA5 돌파에서 나온다.
6. 승인 대기 주문이 뜨면 종목·방향·수량·지정가를 보고 **60초 안에** 승인 또는 거절. 늦으면 `expired`로 닫히고 다음 봉에서 다시 판단한다.
7. 보유가 생기면 손절 0.3%·익절 0.2%·트레일링 0.15%와 15:45 ET(05:45 KST) 청산도 각각 승인해야 나간다. 하루 2건 한도는 새 진입을 막지만, 보호 청산은 한도에 걸려도 승인 대기로 뜬다(ADR 0044 결정 2). 자리를 비우면 팔지 않으므로, 그때는 증권사 앱에서 직접 정리한다.
8. 끝나면 **무장 해제**(또는 킬 스위치). 무장 해제 뒤에 키움 조회 전용 동기화를 돌린다(무장 중에는 같은 키 동기화가 409로 막힘).
9. 끝났다고 이 세션(SIW 실계좌)에 알린다.

## 3. 사후 확인 (코딩 Agent, 읽기만)

```bash
sqlite3 -readonly data/live_orders.sqlite3 "select count(*) from order_intents; select status, count(*) from order_submissions group by status;"
```

- `live_orders.sqlite3`: 의도·확인(`order_confirmations`)·제출·결과·체결. 체결 문서는 `environment: real`, `ledger: broker_live_orders`.
- `~/Library/Logs/siw-agent/live-runner.log`: 토큰 8005 재시도, 호출 한도 오류, 거절 사유.
- 증권사 API 체결 원장(조회 전용 동기화, ADR 0029): 같은 주문이 `order_aggregate`로 들어왔는지, `live_orders`의 체결과 수량·가격이 맞는지. 두 기록은 합치지 않는다.
- ADR 0047에 적을 것: 실전 응답 형식, 체결 시각 형식과 시간대, 호출 한도 오류 여부. 계좌번호·키·주문번호 원문은 적지 않는다.
- 끝나면 `stock-intelligence-61`을 닫고, 아래 표의 "실계좌 승인 체결" 칸을 갱신한다.

## 4. 메리츠 체결 시각 (`stock-intelligence-7`)

메리츠 실계좌 키를 사용자가 등록한 뒤에만 한다. 등록되면 사용자 승인 아래 조회 전용 동기화를 한 번 돌려, 저장된 체결 시각이 어느 시간대인지(증권사 앱의 같은 체결과 비교) 확인한다. 그 전에는 메리츠 동기화 결과의 시각을 믿지 않는다. 지금 상태: 키 등록 소식 없음(미확인).
